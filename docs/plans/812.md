# #812: PauseShard refuses requests and ResumeShard restores them

Objective: one in-process test that drives a single-replica shard through five
PauseShard/ResumeShard cycles and checks the documented contract.

Slice 1 (this lane), `pkg/shard_pause_resume_test.go`:

- `TestShardPauseResume_FiveCycles`: each cycle applies entries with
  SyncPropose, pauses, and asserts SyncPropose, Propose, SyncRead, ReadIndex
  and NewSession return errors matching `ErrShardPaused` (errors.Is).
- A second PauseShard on the paused shard returns nil (documented idempotent).
- The state machine hash, taken while paused, covers every entry applied
  before the pause (an order-independent sum the test also computes).
- After ResumeShard, SyncPropose, Propose, SyncRead and ReadIndex succeed,
  and the hash still covers every earlier entry plus the new ones.

A defect found lands as a failing test commit, then the fix in pkg/host.go.

Out of scope: multi-replica leader hand-off on pause (host_pause_test.go
covers serialization), persistence of the pause across restart, any wire or
on-disk format change.
