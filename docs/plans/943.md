# Plan: #943 automatic snapshots on a Host (Refs #744)

## Objective

`config.Config.SnapshotEntries` and `CompactionOverhead` (pkg/config/config.go)
and docs/snapshots/user.md promise that a shard snapshots on its own every
`SnapshotEntries` applied entries, compacts the log so `CompactionOverhead`
entries stay below the latest snapshot, and that `config.SnapshotsDisabled`
turns automatic snapshots off while `SyncRequestSnapshot` keeps working. The
trigger (pkg/internal/engine/apply.go) is tested in the engine only. This row
tests it through a real Host with an on-disk WAL.

## Slices

1. `docs: plan for #943` — this file.
2. `test:` pkg/host_auto_snapshot_test.go, a key/value state machine that
   counts `SaveSnapshot` calls and records the applied index of each save;
   shard `SnapshotEntries` 20, `CompactionOverhead` 5:
   - `TestAutoSnapshot_TriggersAtSnapshotEntries`: 19 proposals take no
     snapshot; 20 more take at least one within a bounded wait, with no
     `RequestSnapshot` call.
   - `TestAutoSnapshot_CadenceCompactionAndRecovery`: about 100 proposals
     give one snapshot per 20 applied entries (bootstrap and membership
     entries counted in the applied index); `LogRange().FirstIndex` is no
     lower than latest snapshot index minus `CompactionOverhead`; after
     `Close`, a new Host on the same directories recovers every value.
   - `TestAutoSnapshot_DisabledNeverSnapshots`: `SnapshotsDisabled` takes no
     snapshot after 100 proposals; `SyncRequestSnapshot` still succeeds.
3. Per divergence from the docs: a failing `test:` commit, then a `fix:`
   commit in pkg/internal/engine/apply.go or pkg/host.go (or a doc fix in
   docs/snapshots/user.md when the code is right).

## Out of scope

Multi-replica snapshot transfer, encryption, per-request compaction
overrides, and any wire or on-disk format change.
