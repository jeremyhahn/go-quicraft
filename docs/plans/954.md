# Plan: #954 OnMembershipChanged per-replica events

Refs #744 (v1.0.0 bar test gap).

## Objective

Prove `config.EventListener.OnMembershipChanged` (pkg/config/hostconfig.go)
fires on every replica exactly once per applied membership change, carries
that Host's shard and replica IDs, never fires for an ordinary proposal, and
never runs ahead of the membership `SyncGetShardMembership` reports.

## Slices

1. `docs: plan for #954` — this file.
2. `test: ...` — pkg/membership_changed_events_test.go (package quicraft):
   a three-Host mTLS cluster (as newTransferCluster in
   pkg/leader_transfer_test.go) with a counting EventListener per Host.
   - (a) a run of ordinary SyncPropose calls fires no OnMembershipChanged on
     any Host (counts compared against the post-bootstrap baseline);
   - (b) SyncRequestAddObserverWithIdentity of a fourth replica fires exactly
     one OnMembershipChanged on each of the three Hosts, with the shard ID
     and that Host's own replica ID;
   - (c) SyncRequestRemoveNode of that observer fires exactly one more on
     each Host;
   - (d) each callback, on its Host, is followed by a
     `SyncGetShardMembership` on that Host that already shows the change.
   Waits are bounded deadlines; helpers take context.Context first.
3. Per divergence from the docs: a failing `test:` commit, then a `fix:`
   commit in pkg/host.go (or a doc fix in pkg/config/hostconfig.go when the
   code is right).

## Out of scope

- Starting the fourth replica's Host (the observer is only added to and
  removed from the membership; no fourth process is needed for the event).
- Witness and voter adds, witness-policy updates, batching of several
  membership changes into one apply batch.
- Any wire or on-disk format change.
