# Plan: #1166 make the inconclusive leadership tests deterministic

## Objective

`TestIntegration_LeaderStaysLeaderUnderSustainedLoad`
(test/integration/raft/leadership_test.go) ends in `t.Skipf("INCONCLUSIVE ...")`
on two paths (the forgotten-leader branch and `failUnlessStalled`), so a run
that hits them proves nothing. Both guard against the host scheduler freezing
a goroutine (0.37-1.6s recorded) for longer than the suite's 500ms election
timeout floor. The test should drive its condition deterministically and pass
or fail, never skip.

## Slices (one lane, one file)

1. Test change (`leadership_test.go` only):
   - Factor the sampling loop into `watchLeadership`, which records the first
     forgotten leader, advanced term and second leader it sees against a
     baseline, and stops on a term change or a second leader.
   - The load subtest fails (`t.Fatalf`) on any departure and on a missed
     write floor; the write floor scales with the window.
   - Remove `schedulingProbe`, `probeStall`, `stallExcusing`,
     `failUnlessStalled`, `followerStallCeiling`, `electionTimeoutFloor` and
     every `t.Skipf`.
   - Add a control subtest: the same loop, with the baseline leader's host
     closed partway through the window; it fails unless the loop reports the
     advanced term (the detector is not vacuous).
   - On BASE timing (ElectionRTT 10) this may fail under load: that is the
     bug the next commit fixes.
2. Timing change (`leadership_test.go` only):
   - A test-local shard start (`startStableShard`, mirroring
     `(*testCluster).startShard`, MemberIdentities set the same way) with
     `stableElectionRTT` derived from the worst recorded freeze: two
     back-to-back 1.6s freezes silence a heartbeat for 3.2s, so the floor is
     2.5 freezes = 4s (ElectionRTT 80 at the 50ms tick).
   - Budgets (election wait, load window > 2 x floor, control window) are
     derived from that ElectionRTT through test/electionbudget.

## Tests
