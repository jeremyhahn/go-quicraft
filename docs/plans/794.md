# #794: StopShard and StartShard repeated on one Host

Objective: one Host that runs StopShard and then StartShard on the same shard 10
times gets its state back and leaks nothing.

Slice (one, pkg/shard_stop_start_cycle_test.go):

- TestStopStartCycle_RecoversStateAndLeaksNothing: a single-replica shard on the
  default WAL with a state machine whose order-independent hash covers every
  applied command. Each cycle proposes new entries, calls StopShard, calls
  StartShard with the same config, waits for a leader, and asserts
  StateMachineHash equals the hash of every acknowledged command so far, so a
  lost or twice-applied entry fails.
- After the last cycle runtime.NumGoroutine is within a small margin of the
  first cycle's count, and /proc/self/fd does not grow (skipped off Linux).

Existing cover: pkg/host_restart_routing_test.go:46 stops and restarts once and
checks routing only; no test repeats the cycle or checks state or leaks.

Out of scope: multi-replica cycles, snapshots across the cycle, Host restart.
A defect the test finds gets a failing test commit, then the fix.

## Slice 2

- Goroutine check: baseline taken before cycle 0 after runtime.GC and a settle,
  so all 10 cycles are measured; the margin (3) is below the cycle count, so one
  leaked goroutine per cycle fails.
- Descriptor check: skipped only off Linux; on Linux any /proc/self/fd read
  error at any sample fails the test (t.Fatalf), so EMFILE cannot pass.
