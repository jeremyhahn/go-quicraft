# #972: client-sessions guide flows as checked examples

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/client-sessions/user.md shows Go blocks that no example compiles or
runs. Make the async, owner and saved-ID flows checked `Example` functions
so `go test` fails when the guide and the code part ways.

## Slices

1. Plan (this file).
2. `pkg/example_session_test.go` (package `quicraft_test`), reusing
   `startExampleShard` from pkg/example_host_test.go:
   - `ExampleHost_ProposeWithSession`: two `ProposeWithSession` calls with
     `ProposalCompleted` between; both writes are read back.
   - `ExampleHost_NewSessionWithOwner`: the session carries the owner ID
     and a proposal on it is applied.
   - `ExampleHost_RegisterSession`: `NewSession(shardID, savedID)`
     registered, its client ID kept, a proposal on it applied.
   Each ends with an `// Output:` block. The guide's matching blocks name
   their example.
3. Per divergence between code and guide: a failing test commit then a fix
   commit in pkg/host.go or pkg/session.go; a guide that is wrong where the
   code is right is corrected in the guide.

## Out of scope

- The retry block in "Retry safely" (changed separately).
- Session limits, expiry and troubleshooting text.
