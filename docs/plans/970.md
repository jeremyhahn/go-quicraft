# #970: the snapshots guide runs as checked examples

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/snapshots/user.md shows the on-demand snapshot, export and import flows
as Go blocks that nothing compiles or runs. Make each flow a Go example with an
`// Output:` block in pkg/example_snapshot_test.go, so `go test` checks that
the guide's calls do what the guide says, and point each guide block at its
example.

## Slices, in order

1. This plan.
2. Test commit: pkg/example_snapshot_test.go (package quicraft_test), reusing
   `exampleHostConfig`, `waitReadReady` and `startExampleShard` from
   pkg/example_host_test.go:
   - `ExampleHost_SyncRequestSnapshot`: a few writes, then
     `SyncRequestSnapshot` with `DefaultSnapshotOption`; prints that the
     returned index is non-zero.
   - `ExampleSnapshotOption_exportPath`: a `SnapshotOption` with an absolute
     `ExportPath`; prints that the exported snapshot file exists there.
   - `ExampleHost_ImportSnapshot`: `ExportSnapshot` to a buffer, then
     `ImportSnapshot` with `WithImportDataDir("")` into a fresh Host whose
     shard was bootstrapped and stopped; after restart the shard reads the
     written key.
   The guide's matching blocks name their example.
3. Per divergence between code and guide: a failing test commit, then a fix
   commit in pkg/host.go or pkg/snapshot_option.go; a guide that is wrong
   where the code is right is corrected in docs/snapshots/user.md.

## Out of scope

- Re-keying (`ReencryptSnapshotFile`), cadence and transfer-tuning blocks:
  they need a barrier or a multi-node transport and stay prose.
- Any wire or on-disk format change.
