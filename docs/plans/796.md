# #796: Close completes every in-flight request with ErrClosed

Objective: prove `Host.Close` ends every request pending on a shard that
has lost quorum: no caller blocks, every outcome is `ErrClosed` (or
`ErrCanceled`), Close returns within 5s, and no goroutine outlives it.

Existing coverage: `pkg/host_pending_lifecycle_test.go:208`
(`TestPendingRegistration_CloseRace_CallerNeverOrphaned`) races Close
against ReadIndex/RequestSnapshot/RequestAddNode on a live single-node
shard and checks only that callers return; it asserts no error class and
covers neither Propose, SyncPropose nor SyncRead under lost quorum.

Slice 1 (`pkg/host_close_inflight_test.go`, `TestHostClose_CloseInflight...`):
single-node leader (CheckQuorum off) adds an unreachable voter, so quorum
is 2 and nothing commits; 64 goroutines issue Propose, SyncPropose and
SyncRead; wait until all are pending; Close; assert the bounds above.
A defect found: failing test commit first, then the fix.

Out of scope: multi-host partitions, transport-level faults, Drain API.

## Review fix

Close ran synchronously, so a shutdown deadlock hung the test until the
suite timeout. Close now runs in a goroutine that sends on a buffered
channel, selected against a 5s timer that fails the test. The deferred
cleanup checks a test-local flag set before Close starts, so it never
calls Close again on an unfinished shutdown.

## Review fix (round 3)

The baseline `before := h.pendingOps.Load()` was read after the
RequestAddNode result was released, but deliverProposal decrements
pendingOps after it completes the result, so the baseline could read 1
and the wait for 64 pending callers would time out. The test now waits
(10s deadline) for pendingOps to drain to 0 before launching callers and
compares pendingOps to the caller count directly.
