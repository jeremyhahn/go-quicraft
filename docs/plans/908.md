# Plan: #908 connection events (v1.0.0 bar test gap, Refs #744)

## Objective

`EventListener.OnConnectionEstablished` and `OnConnectionFailed`
(pkg/config/hostconfig.go) are documented to fire with a `ConnectionInfo`
whose Address is the peer's raft address, Err set on a failed dial. No test
sets either callback. Add an integration test on the real QUIC transport
that pins the documented behaviour.

## Slices

1. This plan.
2. test/integration/host/connection_events_test.go (`//go:build integration`),
   `TestConnectionEvents_PeerAddress`: two hosts, each with an EventListener
   that records ConnectionInfo under a mutex.
   - (a) after the two-voter shard elects a leader, each host has seen
     `OnConnectionEstablished` with Address equal to the other's RaftAddress;
   - (b) after one host closes, the survivor sees `OnConnectionFailed` for
     that address within 30s;
   - (c) no callback reports the host's own address.
   Waits poll with deadlines; no fixed sleeps.
3. Per divergence from the docs: a failing test commit, then a fix in
   pkg/internal/transport/conn.go (or a comment-only doc fix in
   pkg/config/hostconfig.go when the code is right).

## Out of scope

- Other EventListener callbacks; transport unit tests; wire or on-disk
  format changes.
