# Plan for #974: the multi-group-host guide's flows as checked examples

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/multi-group-host/user.md shows Go blocks that no example compiles or
runs. Add `pkg/example_multigroup_test.go` (package `quicraft_test`) with
examples that end in an `// Output:` block, so `go test` checks each flow,
and point the matching guide blocks at them.

## Slices, in order

1. This plan.
2. The examples, reusing `exampleHostConfig`, `waitReadReady` and
   `startExampleShard` from pkg/example_host_test.go:
   - `Example_multipleShards`: one Host runs shards 1 and 2 with separate
     data; a key written to each shard reads back that shard's own value,
     and a key written only to shard 1 is absent from shard 2.
   - `ExampleHost_ExecuteOnLeader`: `RegisterLeaderHandler` then
     `ExecuteOnLeader` returns the handler's reply.
   - `ExampleHost_HealthCheck`: prints `Status` and `ShardCount`.
   - `ExampleHost_ExportSnapshot`: `SyncRequestSnapshot`, then
     `ExportSnapshot` of the shard to a file; prints that the file is
     non-empty.
   The guide's "Run a single node", "Health", "Run a request on the leader"
   and "Back up and restore" blocks name the example that runs them.
3. Per divergence between code and guide: a failing test commit, then a fix
   commit in pkg/host.go or pkg/leaderexec.go; a guide that is wrong where
   the code is right is corrected in the guide.

## Out of scope

Multi-node formation, membership changes, barriers, metrics and import:
they need a transport, identities or a barrier and are covered elsewhere.
No wire or on-disk format change.
