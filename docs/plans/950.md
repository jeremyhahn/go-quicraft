# #950: shamir user guide snippets compile and run as package examples

Refs #744 (v1.0.0 bar test gap).

## Objective

`docs/shamir-primitive/user.md` shows Go snippets for the protected-share
ceremony (`SplitProtected` + `WithValue`, `UnmarshalShareSet` + wipe,
`CombineProtected`). None is compiled, so a renamed or re-signatured function
leaves the guide wrong without a failing build. Add runnable package examples
with `// Output:` lines that follow the guide's code as written, including its
`Destroy` and wipe calls.

## Slices

1. `docs: plan for #950` — this file.
2. `test:` — `pkg/crypto/shamir/example_docs_test.go` (package `shamir_test`):
   - `ExampleSplitProtected`: split a fixed 32-byte key 3-of-5, read each share
     through `WithValue`, print each share's Index and value length, destroy
     every share.
   - `ExampleUnmarshalShareSet`: JSON-encode three shares (the submitted set),
     decode with `UnmarshalShareSet`, `enclave.Wipe` the buffer, combine with
     `CombineProtected`, print whether the secret equals the original.
   - `ExampleCombineProtected`: three of five shares reconstruct the key; two
     of five are refused with a `*CombineError` (the shares carry their
     threshold, so the count check runs against it).
3. Per divergence between code and guide: a failing `test:` commit, then a
   `fix:` commit in `protected_share.go` (or the guide, where the code is
   right).

## Acceptance

- `go test -race -count=3 -run 'Example' ./pkg/crypto/shamir/` passes.
- `go vet ./pkg/crypto/shamir/` passes; `make lint` clean.
- Only File map files change.

## Out of scope

- The `seal`/`barrier` authentication snippet (lines 36-50): it needs a Host
  barrier and is covered by the seal packages' own tests.
- The `SplitBytes`/`CombineBytes` snippets (already `ExampleSplitBytes`).
- Any wire or on-disk format change.
