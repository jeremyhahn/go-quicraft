# #923: QueryRaftLog maxSize, owned copies and range edges

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/multi-group-host/api.md says `QueryRaftLog(ctx, shardID, firstIndex,
lastIndex, maxSize)` returns the entries in `[firstIndex, lastIndex)`, up to
`maxSize` bytes, and fails with `ErrInvalidRange` for `firstIndex >=
lastIndex` or `maxSize == 0`, and with LogDB errors such as
`logdb.ErrCompacted`. Existing tests cover errors or use a large maxSize. This
row pins the size limit, the ownership of the result and the range edges on a
real WAL.

## Slice 1 (this lane)

New pkg/host_query_raft_log_test.go, single-voter transportless Host
(`testHostConfig`, `NewHost(cfg, WithoutTransport(), WithoutEncryption())`,
`testShardConfig`, `waitForLeader`):

- (a) 40 SyncPropose calls of 1 KiB; a query over the 40 with maxSize 4 KiB
  returns at least one entry, starting at firstIndex, consecutive indexes,
  fewer than 40, and a total Cmd size no more than maxSize unless only one
  entry (the documented one-entry minimum).
- (b) a large maxSize returns every entry in the range, none at lastIndex.
- (c) changing a returned Cmd leaves a second query's result unchanged.
- (d) lastIndex past the last entry returns `logdb.ErrUnavailable` (a LogDB
  error, as documented; no clamp); firstIndex == lastIndex and maxSize == 0
  return `ErrInvalidRange`.
- (e) after SyncRequestSnapshot (which compacts the log), a query below the
  first retained index returns `logdb.ErrCompacted`.

Per divergence from the docs: a failing test commit, then a fix commit in
pkg/host.go, or a doc fix in docs/multi-group-host/api.md if the code is
right.

## Out of scope

- LogReader / LogRange behaviour beyond what the queries need.
- Multi-replica and transport paths.
- Any wire or on-disk format change.
