# #797: concurrent SyncPropose applies every entry exactly once

Objective: prove that many goroutines calling `Host.SyncPropose` at once on a
three-replica shard commit and apply each acknowledged entry exactly once on
every replica, apply nothing unacknowledged, and leave identical state.

Existing coverage: `pkg/host_test.go` `TestMultipleConcurrentProposals_Complete`
runs 10 concurrent proposals on a one-replica shard and checks only that each
returns; it checks neither exactly-once application nor replica agreement.

Slice 1 (this lane), `pkg/concurrent_propose_test.go`:
- three in-process hosts over loopback QUIC (the `wireswitch_nextwire_test.go`
  fixture pattern), each running a recording state machine (key -> apply count,
  snapshot-able, order-independent `GetHash`);
- 64 goroutines x 50 `SyncPropose` with unique keys against the leader;
- wait until every replica reaches the leader's applied index, then assert each
  acknowledged key applied exactly once per replica, no other key applied, and
  equal `StateMachineHash` across replicas. Run under `-race`.

Out of scope: proposals across leader changes, sessions, and fault injection.
A defect found gets a failing test commit, then a fix commit.
