# Plan: #975 — the memory-enclave guide's flows run as checked examples

Tracked under #744 (v1.0.0 bar test gap).

## Objective

docs/memory-enclave/user.md shows Go blocks that no example compiles or runs.
Turn each flow into a Go example with an `// Output:` block in
pkg/seal/example_enclave_test.go (package `seal_test`), so `go test` checks
it, and point each guide block at its example.

## Slices, in order

1. This plan.
2. Test commit: pkg/seal/example_enclave_test.go adds
   - `Example_enclaveNewSealed`: `enclave.NewSealed` on a byte slice; the input
     is all zero afterwards and `Open` + `WithBytes` returns the original bytes.
   - `Example_enclaveWithBytes`: a sealed key opened and used inside
     `WithBytes` for an AES-GCM seal and open round trip; `Destroy` of the key
     makes a later `Open` fail with `ErrEnclaveDestroyed`.
   - `Example_enclaveNewMemorySized`: a sized buffer filled in place, frozen
     through `enclave.As` to `Freezer`; a capability the memory enclave lacks
     (`AEAD`) is refused by `As` and reported as a `*CapabilityError` matching
     `ErrCapabilityUnsupported`.
   - `Example_enclaveWipe`: `enclave.Wipe` zeroes a transient slice.
   - `Example_enclaveNewCredentials`: `seal.NewCredentials` consumes the
     passphrase, the secret opens to it, and after `Destroy` an `Open` fails
     with `ErrEnclaveDestroyed`.
   The guide's matching blocks each name their example.
3. Per divergence between code and guide: a failing test commit, then a fix
   commit in pkg/seal/strategy.go (or a doc fix in user.md where the code is
   right).

## Out of scope

- go-enclave itself (a separate module); any wire or on-disk format.
- Guide sections without a Go block (troubleshooting).
