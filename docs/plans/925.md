# Plan #925: many shards on one Host

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/multi-group-host/user.md says one Host runs many shards that share its
WAL and workers while each keeps its own log and state. No test starts more
than a few shards on one Host. Pin the claim with a test that runs two
hundred single-voter shards on one transportless Host with a real WAL.

## Slices

1. `docs: plan for #925` — this file.
2. `test: two hundred shards on one Host ...` — pkg/host_many_shards_test.go,
   `TestHost_ManyShards_IsolatedStopAndRestart`:
   - (a) start 200 single-voter shards with `hashingCreateFunc`; `ShardCount`
     is 200 and `NodeHostInfo` lists 200 shards;
   - (b) 16 goroutines propose a distinct command sequence to each shard; each
     shard's `StateMachineHash` equals its pre-proposal hash plus a replay of
     only its own sequence at the indexes that follow its pre-proposal
     applied index;
   - (c) stop the 100 even shards; `ShardCount` is 100; every odd shard
     accepts a `SyncPropose`; every even shard returns `ErrShardNotFound`;
   - (d) Close, open a new Host on the same directories, start all 200
     again; every shard's hash equals its value before the restart.
3. Per divergence between code and doc: a failing `test:` commit, then a
   `fix:` commit in pkg/host.go (or a doc fix in
   docs/multi-group-host/user.md when the code is right).

Acceptance: `go test -race -count=2 -run ManyShards ./pkg/` passes in under
60 s per run; `go vet ./pkg/` passes.

## Out of scope

- Multi-host or transport-backed shards; snapshots and log compaction.
- Throughput or latency measurement.
