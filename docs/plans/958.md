# Plan for #958: BarrierConfig.AEADProvider test gap

Refs #744 (v1.0.0 bar test gap).

## Objective

`BarrierConfig.AEADProvider` (pkg/seal/barrier_config.go) is documented as a
custom cipher.AEAD factory, nil meaning `SoftwareAEADProvider`. The barrier
installs it in `NewBarrier` and calls it through `deriveEpochCipher` for every
epoch key, including in `Rotate`, which treats it as third-party code that may
fail or panic. No test sets it. This lane adds that test and fixes the code (or
the doc) where they disagree.

## Slices, in order

1. This plan (`docs: plan for #958`).
2. `pkg/seal/aead_provider_config_test.go` (package seal), with a recording
   provider that counts calls, records algorithm and key length, delegates to
   `SoftwareAEADProvider`, and can be told to fail or panic:
   - (a) Initialize calls it with the configured algorithm and a key of that
     algorithm's size; encrypt then decrypt round-trips.
   - (b) Rotate calls it again for the new epoch; both epochs decrypt.
   - (c) a provider error on Rotate is returned (errors.Is), the epoch is
     unchanged, old data decrypts and new data encrypts under the old epoch.
   - (d) a provider panic on Rotate, recovered by the test, leaves the epoch
     unchanged and the barrier usable.
   - (e) Seal then Unseal with the same provider reads pre-seal data.
   - (f) nil provider and explicit `SoftwareAEADProvider` decrypt each other's
     ciphertext under the same root key and salt (shared sealed state).
   - (g) `SoftwareAEADProvider.NewAEAD` returns `ErrUnsupportedAlgorithm` for an
     unknown algorithm and `ErrInvalidKeySize` for a wrong key length.
3. Per divergence found: a failing `test:` commit, then a `fix:` commit in
   pkg/seal/barrier.go (or a doc fix in barrier_config.go / aead_provider.go).

## Out of scope

Hardware-backed providers, caller-nonce AEAD shapes (covered by
barrier_chacha_test.go), any wire or on-disk format change.
