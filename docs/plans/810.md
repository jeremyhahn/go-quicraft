# #810: a removed replica stops serving and its ID cannot be added back

## Objective

Prove on three real in-process hosts that removing a follower takes it out of
the linearizable membership, stops its Host applying new entries, and that a
later add of the same replica ID fails with `ErrNodeRemoved` while the shard
keeps committing proposals.

## Slices

1. `pkg/membership_remove_readd_test.go`: `TestRemoveReadd_...` starts a
   three-replica shard over the real transport, proposes, removes a follower
   with `SyncRequestRemoveNode`, checks `SyncGetShardMembership`, checks the
   removed Host's LastApplied stays put while the others advance, then checks
   `SyncRequestAddNode` with the same ID errors with `errors.Is(ErrNodeRemoved)`.
2. If the test finds a bug: a failing-test commit, then the fix in `pkg/host.go`.

## Out of scope

Wire or on-disk format changes; replica-ID recycling (IDs are never reused).
