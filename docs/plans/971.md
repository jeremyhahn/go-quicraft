# Plan for #971: membership-changes guide flows as checked examples

Refs #744 (v1.0.0 bar test gap).

## Objective

`docs/membership-changes/user.md` shows Go blocks that no example compiles or
runs. Add runnable `Example` functions whose `// Output:` blocks `go test`
checks, and point each matching guide block at its example.

## Slices, in order

1. This plan.
2. `pkg/example_membership_test.go` (package `quicraft_test`), reusing
   `startExampleShard` from `pkg/example_host_test.go`:
   - `ExampleHost_SyncGetShardMembership`: a running single-node shard lists
     one voter, and its `ConfigChangeID` is non-zero.
   - `ExampleHost_SyncRequestAddObserverWithIdentity`: an observer added with
     its identity is listed in `Observers`, with its committed identity in
     `Identities`.
   - `ExampleHost_SyncRequestRemoveNode`: the observer, once removed, is gone
     from `Observers` and listed in `Removed`.
   The guide's "pattern", "add an observer", "remove a replica" and "check
   who is in the shard" blocks name the example that runs them.
3. Per divergence between code and guide: a failing test commit, then a fix
   commit in `pkg/host.go`; a wrong doc is corrected in the guide instead.

## Out of scope

- Multi-host flows (starting the joiner, leader transfer, `StopShard` and
  `RemoveData` on the removed node): a single-node example has no second
  host.
- Witness policy and promotion examples.
- Any wire or on-disk format change.
