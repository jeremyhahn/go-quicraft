# #961: CRL revocation across real hosts

Refs #744 (v1.0.0 bar test gap).

## Objective

`pkg/config/transportconfig.go` documents CRL revocation (`RevocationConfig`:
`CRLPaths`, `CheckInterval`, `Mode`, `OnCertRevoked`), but no integration test
drives it across live hosts. Prove, on a three-host shard, that a host whose
leaf a CRL revokes while it is stopped is refused when it restarts, that the
surviving hosts report the revoked serial (lowercase hex) through
`OnCertRevoked`, and that the surviving two keep committing.

## Slices, in order

1. `test/testpki/testpki.go`: `(*CA) CRL(t, revoked ...*config.MTLSConfig) []byte`
   returns a PEM `X509 CRL` signed by the CA listing each leaf's serial
   (no arguments: an empty, valid CRL). It is exercised by slice 2; the File
   map admits no new unit-test file in `test/testpki`.
2. `test/integration/host/crl_revocation_test.go`
   (`TestHostAPI_CRLRevocation_ThreeNode`):
   - (a) three hosts, one CRL file each, `Mode: "crl"`, a short
     `CheckInterval`, starting from an empty CRL; a shard commits;
   - (b) host 3 stops; a CRL revoking host 3's leaf is written to every CRL
     file; the test waits past one `CheckInterval`;
   - (c) host 3 restarts on its directories, address and leaf: hosts 1 or 2
     call `OnCertRevoked` with host 3's serial, host 3 never applies a write
     made after its restart, and a fresh handshake presenting host 3's leaf
     is refused by hosts 1 and 2;
   - (d) a proposer runs from before the stop to the end: every proposal to
     hosts 1-2 commits.
3. Per divergence between code and docs: a failing test commit, then a fix in
   `pkg/internal/transport/revocation/` (or a doc fix in
   `pkg/config/transportconfig.go` when the code is right).

## Out of scope

OCSP and the "both"/"any" modes; revocation of a live, established
connection; CA rotation (covered by `ca_rollover_test.go`).
