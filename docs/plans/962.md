# Plan: #962 apply-path decompression bound (Refs #744)

## Objective

Cover `checkDecompressedSize` (pkg/internal/engine/apply.go) and the apply
worker's use of it with the entry size limit: a compressed entry whose
snappy header declares more than `MaxEntrySize` decoded bytes fails the
shard with `raft.ErrDecompressionBomb` before any buffer is allocated and
before the state machine sees it.

## Slices

1. Test commit: pkg/internal/engine/apply_decompress_bound_test.go
   - (a) `checkDecompressedSize`: maxSize+1 declared -> ErrDecompressionBomb;
     exactly maxSize -> nil; uncompressed of any size -> nil; maxSize <= 0
     -> nil for any input.
   - (b) unreadable snappy header -> `*raft.DecompressError`.
   - (c) apply worker: a bomb entry fails the shard with
     ErrDecompressionBomb, no Update, lastApplied unchanged.
   - (d) apply worker: a valid compressed entry under the limit is applied
     with its decompressed command.
2. Per divergence between code and doc: failing test commit, then fix in
   apply.go (or a doc-comment correction where the code is right).

## Out of scope

- raft.DecompressEntries itself, snapshot/transport decompression, any
  wire or on-disk format change.
