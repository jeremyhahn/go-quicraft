# Plan for #910: seal.ShamirInitResult JSON round trip and edge cases

Refs #744 (v1.0.0 bar test gap).

## Objective

`pkg/seal/shamir.go` documents how `ShamirInitResult` encodes and decodes as
JSON. The existing tests check the wire shape, an oversized share set and a
partial failure. None of them combines decoded shares back into the secret,
and none checks the null, empty-array or reused-receiver rules. This row adds
tests for those rules.

## Slices

1. `docs: plan for #910`: this file.
2. `test: ...`: new `pkg/seal/shamir_initresult_json_test.go`, using
   `splitForResult` from `shamir_test.go`:
   - (a) a 2-of-3 result is marshalled and unmarshalled. It keeps Threshold 2
     and TotalShares 3, and `CombineProtected` of every pair of decoded
     shares returns the original secret;
   - (b) a document with `shares` absent, and one with `"shares":null`,
     decode with no shares and no error;
   - (c) a document with `"shares":[]` is rejected;
   - (d) unmarshalling into a receiver that already held shares destroys
     them: each old share then has `Validate() != nil`;
   - (e) unmarshalling malformed JSON into a receiver that holds shares
     returns an error, and each held share still has `Validate() == nil`.
3. For each case where the code differs from the doc: a commit with the
   failing test, then a `fix:` commit in `pkg/seal/shamir.go`. If the code is
   right and the doc is wrong, the doc comment is corrected instead.

## Out of scope

- Any change to the wire format, the share encoding or a format version.
- `UnmarshalShareSetWith` and other decode paths that take an allocator.
