# Plan for #952: HasNodeInfo true-path coverage

Refs #744 (v1.0.0 bar test gap).

## Objective

`Host.HasNodeInfo` (pkg/host.go) reports whether bootstrap information for a
shard/replica pair exists in the LogDB. Existing tests only cover the false
results (closed Host, unknown pair). Add a test that asserts the true result
and its lifetime: across a restart, independence between pairs and shards,
and removal by `RemoveData`.

## Slices

1. `docs: plan for #952` (this file).
2. `test:` pkg/host_has_node_info_test.go, package quicraft, a Host on real
   WAL and NodeHost directories (t.TempDir), no transport, no encryption:
   - (a) after StartShard of shard 1 replica 1 and a committed proposal,
     `HasNodeInfo(1, 1)` is true; `HasNodeInfo(1, 2)` and `HasNodeInfo(2, 1)`
     are false.
   - (d) a second shard (2, replica 1) started on the same Host is reported
     true while (2, 2) stays false; stopping and removing one shard does not
     change the other's result.
   - (b) after Close and a new Host on the same directories and identity,
     `HasNodeInfo(1, 1)` is true before StartShard is called again.
   - (c) after StopShard and SyncRemoveData of (1, 1), `HasNodeInfo(1, 1)` is
     false, and stays false after a further restart on the same directories.
   Waits use bounded deadlines (waitForLeader, context timeouts), no bare
   sleep.
3. Per divergence between the code and its doc comment: a failing `test:`
   commit, then a `fix:` commit in pkg/host.go (or a doc fix where the code
   is right).

## Out of scope

- Transport, encryption, and multi-Host clusters.
- Any change to the LogDB format or the RemoveData retirement semantics.
