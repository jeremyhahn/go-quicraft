# #816: SyncRemoveData deletes a stopped replica's data and refuses a running one

Objective: prove on an in-process three-replica shard (real WAL, mTLS) that
`RemoveData`/`SyncRemoveData` refuse a running replica and remove a stopped one.

Slice 1 (pkg/replica_remove_data_test.go):
- propose entries; `SyncRemoveData` and `RemoveData` on a running follower
  return an error matching `ErrShardNotStopped` (errors.Is); its LogDB state
  and snapshot directory are unchanged.
- `StopReplica` the follower, `SyncRemoveData` it: LogDB holds no state,
  bootstrap or entries for it and reports it removed.
- RemoveData retires the replica ID (documented, host.go RemoveData doc): a
  restart under the same config is refused with `ErrReplicaRetired`; the
  replica rejoins under a new ID (delete 3, add 4) and its `StateMachineHash`
  reaches the leader's.
- the other two replicas accept proposals throughout.

A removal bug found here gets a failing test commit, then a fix in pkg/host.go.
Out of scope: wire or on-disk format changes; other packages.
