# Plan: #936 Host.ID persistence (v1.0.0 bar test gap, Refs #744)

## Objective

Prove that the identifier a real Host reports through `ID()` follows the
`HostConfig.HostID` documentation in pkg/config/hostconfig.go: when empty it
is loaded from `NodeHostDir/host.id`, or, when that file is absent or
malformed, generated as 32 hex characters and written there with mode 0600.

## Slices

1. `docs: plan for #936` (this file).
2. `test: ...` adds pkg/host_id_persistence_test.go, `TestHostIDPersist*`:
   - (a) a Host with no `HostID` reports 32 lowercase hex characters;
     `host.id` holds the same value with mode 0600;
   - (b) after `Close`, a new Host on the same `NodeHostDir` reports the
     same `ID()`;
   - (c) a Host on another empty directory reports a different `ID()`;
   - (d) a Host with `HostID` set reports that value and leaves the
     `host.id` written in (a) unchanged;
   - (e) a `host.id` with malformed content (wrong length, non-hex, trailing
     newline) is replaced by a new valid ID with mode 0600, and the Host
     never reports the malformed value.
3. Per divergence from the docs: a failing `test:` commit, then a `fix:`
   commit in pkg/host.go (or a doc fix in pkg/config/hostconfig.go when the
   code is right).

## Out of scope

- Any change to the host.id format, length or file name.
- Persistent LogDB and transport paths; the tests use the in-memory LogDB
  and no transport, as `newTestHost` does.
