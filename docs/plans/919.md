# Plan: #919 Entry.Cmd ownership with and without ZeroCopyEntryCmd

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/state-machines/user.md, docs/state-machines/architecture.md and
`config.Config.ZeroCopyEntryCmd` say `Entry.Cmd` is an owned copy by
default (a state machine may keep it after `Update` returns), and that
with `ZeroCopyEntryCmd` true `Cmd` aliases engine memory reused after the
apply, so a state machine must copy what it keeps (`Entry.CopyCmd`). The
flag is tested only inside pkg/internal/rsm; no Host test sets it. Pin the
contract at the Host level.

## Slices

1. This plan.
2. pkg/host_zero_copy_cmd_test.go, on a single-voter transportless Host
   (`WithMemoryLogDB`, `WithoutTransport`, `WithoutEncryption`) with a
   local state machine that keeps both the raw `Cmd` slice and
   `CopyCmd()` of every entry and returns the entry index as the result:
   - (a) ZeroCopyEntryCmd false: 300 distinct 512-byte payloads, half
     proposed in sequence and half from 4 goroutines with SyncPropose;
     every kept raw slice equals the payload proposed at its index.
   - (b) ZeroCopyEntryCmd true, same payload set: every `CopyCmd()` copy
     equals its payload, and the order-independent state machine hash
     (via `Host.StateMachineHash`) equals the hash from (a).
   - (c) ZeroCopyEntryCmd true with `kv.NewConcurrentCreateFunc()`: 200
     keys written with SyncPropose each read back with SyncRead as the
     value written.
3. Per divergence from the docs: a failing test commit, then a fix in
   pkg/internal/rsm/statemachine.go or pkg/sm/kv/concurrent.go (or a doc
   correction in docs/state-machines/user.md when the code is right).

## Out of scope

- Asserting raw slices are overwritten under ZeroCopyEntryCmd: reuse is
  allowed, not promised, and reading them would race the engine.
- Disk and on-disk state machines, multi-replica clusters, snapshots.
