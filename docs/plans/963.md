# #963: write-batching guide snippets as compiled examples

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/write-batching/user.md shows three code blocks no build checks: the
`batch.DecodeBatch` loop in an `Update`, the `*batch.FlushError` /
`batch.ErrQueueFull` switch, and `writemode.FromString` / `Validate`. Make
each one a compiled Go example with an `// Output:` block, and point the
guide at it.

## Slices, in order

1. This plan.
2. Test commit:
   - `pkg/batch/example_test.go` (package `batch_test`):
     - `ExampleDecodeBatch`: `EncodeBatch` three commands; `DecodeBatch`
       returns them in order; an empty entry returns `nil, nil`.
     - `ExampleFlushError`: an `Aggregator` from `NewAggregator` over an
       in-test fake `Proposer` that fails; `Submit` returns an error
       matching `*batch.FlushError` with the shard ID and `Indeterminate`
       as documented (definite for a plain failure, indeterminate for a
       propose timeout); `Close` returns nil.
   - `pkg/writemode/example_test.go` (package `writemode_test`):
     - `ExampleFromString`: every documented name round-trips through
       `String`; `IsSynchronous` / `IsAsync` / `RequiresQuorum` print as
       the guide states (`Batched` requires quorum); an unknown name and an
       unknown `Mode` return an error matching `*writemode.InvalidModeError`.
   - docs/write-batching/user.md: each of the three blocks names its
     example.
3. Per divergence between code and guide: a failing test commit, then a fix
   commit in pkg/batch/ or pkg/writemode/; a wrong doc is corrected in the
   guide instead.

## Out of scope

- Any change to the batch wire format or a format version.
- Examples for the other guide blocks (aggregator wiring, tuning,
  SubmitNoCopy, shutdown).
