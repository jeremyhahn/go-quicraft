# #781: snapshot round trip keeps state for every compression type

Objective: for each type in `validCompressionTypes` (pkg/config/compression.go),
an in-process shard saves a snapshot and a restarted replica recovers the same
state-machine hash from it; an invalid type is refused by config validation.

Existing coverage (cited, not duplicated):
- pkg/config/config_test.go:366 rejects an invalid type in `Config.Validate`.
- pkg/snapshot_integrity_test.go:256 covers export/import across compression
  settings, not a save-then-restart recovery.

Slice (one commit, pkg/snapshot_compression_roundtrip_test.go):
1. TestSnapshotCompression_RoundTripKeepsState: per valid type, on-disk WAL host,
   apply entries, SyncRequestSnapshot, record StateMachineHash, check the
   logdb snapshot record carries the type, close, reopen the host, StartShard,
   assert the state machine recovered from the snapshot and the hash matches.
2. TestSnapshotCompression_InvalidTypeRejected: StartShard with an unknown type
   fails with a *config.ValidationError naming SnapshotCompressionType.

Out of scope: wire/on-disk format changes; entry compression round trips.
