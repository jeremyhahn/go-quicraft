# Plan: #844 — waldb Open refusals with their named errors

## Objective

docs/log-storage/api.md (Barrier, Errors) and docs/log-storage/engineering.md
(options table) say `waldb.Open` refuses:

- a `MaxFileSize` smaller than two blocks with `ErrSegmentTooSmallForEntry`,
  a check `Options.Validate` does not make;
- a barrier with `EncryptWithContext`, `DecryptWithContext`, `IsHardwareMode`
  and `SupportsContextAAD` but no `ContextBindingResolved` with
  `ErrBarrierContextBindingUnreportable`, not `ErrBarrierContextUnsupported`.

No test names either sentinel. This row pins both, plus the option errors.

## Slices

1. This plan.
2. `pkg/logdb/waldb/open_refusal_test.go`, every test `TestOpenRefuses*`:
   - `WithMaxFileSize(2*bs-1)` fails with `ErrSegmentTooSmallForEntry` and a
     nil `*DB`; `2*bs` opens and closes;
   - `Options{WALDir, BlockSize: bs, MaxFileSize: 2*bs-1}.Validate()` is nil;
   - a barrier embedding `noContextBarrier` plus the four context methods,
     without `ContextBindingResolved`, fails with
     `ErrBarrierContextBindingUnreportable` and not
     `ErrBarrierContextUnsupported`;
   - `Open("")`, `WithMaxFileSize(maxSegmentFileSize+1)` and
     `WithBlockSize(3000)` fail with `ErrEmptyWALDir`, `ErrInvalidMaxFileSize`
     and `ErrInvalidBlockSize`.
3. Per divergence: a failing test commit, then a fix in
   `pkg/logdb/waldb/db.go` (or a doc fix in docs/log-storage/api.md when the
   code is right).

## Out of scope

- Adding the two-block check to `Options.Validate`.
- Any wire or on-disk format change.
