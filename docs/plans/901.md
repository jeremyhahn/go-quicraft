# Plan: #901 system event callbacks across a Host's lifecycle

Refs #744 (v1.0.0 bar test gap).

## Objective

Pin the documented contract of the system event callbacks
(docs/multi-group-host/api.md "System events" and "Close";
pkg/config/hostconfig.go EventListener):

- `OnNodeReady` fires when StartShard has loaded a replica;
- `OnMembershipChanged` fires after an applied entry changed the membership;
- `OnNodeUnloaded` fires when a replica has been stopped and unloaded;
- `OnNodeDeleted` fires after RemoveData has deleted a replica's data;
- `OnNodeHostShuttingDown` fires once, when Close begins (first caller only).

## Slices

1. Test: pkg/host_lifecycle_events_test.go,
   `TestLifecycleEvents_SystemCallbacksFireOnceWithShardAndReplica`.
   A transportless Host (testHostConfig, memory LogDB) with an EventListener
   recording every system callback (mutex-guarded slice of name, ShardID,
   ReplicaID). Steps and assertions:
   - StartShard(1,1) + waitForLeader: exactly one OnNodeReady{1,1};
   - SyncRequestAddObserver of replica 2: at least one more
     OnMembershipChanged{ShardID 1} than before the change;
   - StopShard(1): exactly one OnNodeUnloaded{1,1};
   - SyncRemoveData(ctx,1,1): exactly one OnNodeDeleted{1,1};
   - Close twice in sequence and from several goroutines at once: exactly
     one OnNodeHostShuttingDown, and no OnNodeReady after it;
   - no recorded shard event carries a zero ShardID.
2. Per divergence from the docs: a failing test commit, then a fix commit in
   pkg/host.go (or a doc correction in docs/multi-group-host/api.md where
   the code is right).

## Out of scope

Raft, snapshot, connection and failure events; multi-host transport runs;
any change to wire or on-disk formats.
