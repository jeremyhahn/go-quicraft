# #752: every exported identifier in a public package has a doc comment

## Review fix

- Gap: `undocumentedDecls` skipped a whole `GenDecl` once it had a doc, so a
  documented `type ( Foo struct{}; Bar struct{} )` block passed with neither
  type documented.
- Fix: the block-level exemption applies to `const` and `var` groups only. In a
  grouped `type (...)` block every exported `TypeSpec` needs its own doc; a
  standalone `type X ...` keeps using the `GenDecl` doc.
- Test: a negative fixture (documented grouped type block, undocumented types)
  asserts the gate reports both types. The stricter gate finds no exported
  grouped type without a doc on this branch, so no doc-comment commit.

## Review fix 2

- Gap: methods were checked only as `FuncDecl`, so explicit methods of an
  exported interface were never checked.
- Fix: every exported `TypeSpec` whose type is an interface has each exported,
  undocumented method field reported as `method <Type>.<Name>`, whatever the
  `GenDecl` doc; embedded fields are skipped.
- Test: `TestUndocumentedDeclsInterfaceMethods` (standalone, grouped and
  unexported interfaces); then doc comments for every method the gate reports.
