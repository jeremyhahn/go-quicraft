# Plan: #977 session.Manager.SetLimits test gap

Refs #744 (v1.0.0 bar test gap).

## Objective

`Manager.SetLimits` (pkg/internal/session/manager.go) has no unit test. Its
doc comment promises that a zero total or response limit is ignored, that the
per-owner cap is always assigned (zero turns it off), and that lowering a limit
evicts no session. Pin each promise with a test.

## Slices

1. `docs: plan for #977` — this file.
2. `test:` pkg/internal/session/set_limits_test.go (package session):
   - (a) `SetLimits(0, 0, x)` keeps the previous total and `MaxResponses`.
   - (b) a per-owner cap of 0 turns the cap off (one owner registers past the
     old cap); a non-zero cap set later is enforced on the next `Register`.
   - (c) lowering the total below `Count` evicts nobody; the next `Register`
     returns `ErrSessionLimitExceeded`; after enough `Unregister` calls a
     `Register` succeeds again.
   - (d) lowering the response limit makes `CanRecord` and `RecordResult`
     refuse at the new bound for a session that already holds responses,
     while `CheckDuplicate` still returns the held responses.
   - (e) a raised total admits new registrations at once.
3. Per divergence between code and doc: a failing `test:` commit, then a
   `fix:` commit in manager.go. None expected: the code was read against its
   doc comment before the test was written.
