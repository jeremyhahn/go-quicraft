# #792: a Host restarted on the same directories with a different identity is refused

Objective: prove that `NewHost` on a WALDir/NodeHostDir that a Host with a
different DeploymentID already used is refused with `ErrHostIdentityMismatch`
(matched with `errors.Is`), leaves both directories byte-for-byte unchanged,
and that a restart under the original identity recovers the applied state.

Existing coverage: `pkg/host_dirlock_test.go:161` (refusal on empty
directories, original identity restarts) and `pkg/host_dirlock_test.go:189`
(address change is not a mismatch). Neither applies entries, checks the
directories after the refusal, or checks recovered state.

Slice (one): `pkg/host_identity_restart_test.go`
- `TestNewHost_IdentityRestartRefusedLeavesDirectories`: start a Host, start a
  shard with a counting state machine, propose entries, close; snapshot both
  directory trees; `NewHost` under another DeploymentID returns
  `ErrHostIdentityMismatch`; both trees are unchanged; `NewHost` under the
  original identity starts, the restarted shard replays the log and a read
  returns the applied entries.

Out of scope: the identity file format and any on-disk format version.
