# #983: grow a shard from one host to five and shrink it back to one

Refs #744 (v1.0.0 bar test gap).

## Objective

`test/integration/e2e/membership_test.go` adds and removes a single replica.
Nothing grows a shard step by step to five voters and shrinks it back to one.
This plan adds an end-to-end test that does, and checks that every
acknowledged write survives with exactly one leader after each change.

## Slices, in order

1. `docs: plan for #983`: this file.
2. `test: a shard grown from one host to five ...`: new
   `test/integration/e2e/grow_shrink_test.go` (package e2e), test
   `TestE2E_GrowShrink_OneToFiveToOne`:
   - (a) grow: start one host with shard 1, write keys. For replicas two to
     five, one at a time: build a new host from the cluster CA, propose
     `SyncRequestAddNodeWithIdentity` with its node identity and the
     leader's current `Membership.ConfigChangeID`, start the shard in join
     mode, wait until the new replica has applied every acknowledged key,
     assert exactly one leader, write more keys.
   - (b) shrink: remove replicas five to two, one at a time, again with the
     current `ConfigChangeID`. Leadership is moved to the replica being
     removed before replicas five and three are removed, so the leader is
     removed at least once (twice). After each removal the removed host is
     stopped, exactly one leader is asserted, and a write must succeed.
   - (c) end: the last host (replica one) reads back every acknowledged key
     with its value through `SyncRead`, and its `ShardMembership` lists
     only replica one in `Nodes` with replicas two to five in `Removed`.
   - Runtime budget: under two minutes; a context with that deadline
     bounds every helper.
3. Per bug found: a failing `test:` commit, then a `fix:` commit in
   `pkg/host.go` (a doc comment that is wrong where the code is right is
   corrected in place instead).

Every new helper takes `context.Context` first, before `*testing.T`.

## Out of scope

- Observers and witnesses; concurrent membership changes.
- Restarting removed hosts or re-adding a removed identity.
- Any wire or on-disk format change; any change outside the file map.
