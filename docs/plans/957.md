# #957: config safety-flag getters and disabled-flag warnings

Tracked under #744 (v1.0.0 bar test gap).

## Objective

Pin the documented behaviour of the Raft safety flags in `pkg/config`:

- `GetCheckQuorum`, `GetPreVote` and `GetOrderedConfigChange` return true when
  the field is nil and the field's value otherwise.
- `Config.Validate` emits one slog warning per safety flag explicitly set to
  false (CheckQuorum, PreVote, OrderedConfigChange), and none when each is nil
  or true.
- `HostConfig.Validate` emits one warning naming NoSyncWAL when it is true, and
  none when it is false.
- A disabled flag is a warning, never an error: Validate returns nil.

## Slices

1. `docs/plans/957.md` (this file).
2. `pkg/config/safety_flags_test.go`:
   - `TestSafetyFlag_GetPreVote`, `TestSafetyFlag_GetOrderedConfigChange`:
     nil, &true, &false.
   - `TestSafetyFlag_ValidateNoWarningWhenEnabled`: all nil, all true.
   - `TestSafetyFlag_ValidateWarnsPerDisabledFlag`: each flag alone false
     gives exactly one warning naming it; all three false gives three, one
     per flag; Validate returns nil in every case.
   - `TestSafetyFlag_HostConfigNoSyncWAL`: one warning naming NoSyncWAL when
     true, none when false; Validate returns nil.
   The slog default logger is swapped for a buffer-backed handler and
   restored with t.Cleanup; these tests are not parallel.
3. Per divergence from the docs: a failing test commit, then a fix commit in
   `pkg/config/config.go` or `pkg/config/hostconfig.go` (or a doc fix when the
   code is right).

## Out of scope

- Any change to how the flags are consumed by the raft or engine packages.
- Wire or on-disk formats.
