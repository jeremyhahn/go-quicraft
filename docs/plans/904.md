# Plan for #904: NewSessionWithOwner enforces MaxSessionsPerOwner

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/client-sessions/api.md says `Host.NewSessionWithOwner` registers a
session counted against the shard's `Config.MaxSessionsPerOwner`; past the cap
registration fails with `*SessionError` (Op "register") wrapping
`ErrInvalidOperation`; `CloseSession` frees the owner's slot; owner 0 is never
counted; `Session.OwnerID` returns the owner.

## Status

The coverage this row planned, (a)-(e) below, landed on main in #846
(`pkg/host_session_owner_test.go`, `TestHostSessionOwnerCap`):

- (a) two owner-7 sessions succeed, each `OwnerID()` is 7;
- (b) a third owner-7 session fails: `*SessionError` wrapping
  `ErrInvalidOperation`;
- (c) another owner and plain `NewSession` (owner 0) still succeed;
- (d) after `CloseSession` of one owner session, a new one succeeds;
- (e) a session passed to `RegisterSession` counts against the same cap.

This row's duplicate test file (`pkg/host_session_owner_cap_test.go`) is
removed. The PR adds only the one assertion main lacked: the refusal's
`SessionError.Op` is "register", in main's `requireOwnerCapRefusal`.

## Out of scope

Multi-replica cap replication, cap changes via membership policy updates,
expiry-driven slot release, on-disk state machines.
