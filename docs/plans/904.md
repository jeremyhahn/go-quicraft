# Plan for #904: NewSessionWithOwner enforces MaxSessionsPerOwner

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/client-sessions/api.md says `Host.NewSessionWithOwner` registers a
session counted against the shard's `Config.MaxSessionsPerOwner`; past the cap
registration fails with `*SessionError` (Op "register") wrapping
`ErrInvalidOperation`; `CloseSession` frees the owner's slot; owner 0 is never
counted; `Session.OwnerID` returns the owner. No test calls
`NewSessionWithOwner`. This row adds that test.

## Slices

1. `pkg/host_session_owner_cap_test.go`, one single-voter transportless Host
   with `MaxSessionsPerOwner = 2`:
   - (a) two owner-7 sessions succeed, each `OwnerID()` is 7;
   - (b) a third owner-7 session fails: `*SessionError`, Op "register",
     `errors.Is(err, ErrInvalidOperation)`;
   - (c) owner 8 and plain `NewSession` (owner 0) still succeed;
   - (d) after `CloseSession` of one owner-7 session, a new one succeeds;
   - (e) a session from package-level `NewSessionWithOwner(shard, client, 7)`
     passed to `RegisterSession` counts against the same cap.
2. Per divergence from the docs: a failing test commit, then a fix commit in
   pkg/host.go (or a doc fix in docs/client-sessions/api.md when the code is
   right).

## Out of scope

Multi-replica cap replication, cap changes via membership policy updates,
expiry-driven slot release, on-disk state machines.
