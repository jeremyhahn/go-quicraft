# #909: snapshot catch-up transfer events

Refs #744 (v1.0.0 bar test gap).

## Objective

`config.EventListener` documents `OnSnapshotSendStarted`, `OnSnapshotSent`,
`OnSnapshotSendAborted` and `OnSnapshotReceived`, each carrying a
`config.SnapshotInfo` (ShardID, ReplicaID, Index, From, Err). No test checks
these callbacks on a real transfer. Prove them on the real QUIC transport.

## Slices

1. Plan (this file).
2. Test `test/integration/host/snapshot_transfer_events_test.go`
   (`//go:build integration`), `TestHostAPI_SnapshotTransferEvents`:
   a one-voter shard with `testShardConfigWithSnapshot(.., 100, 10)` and a
   recording EventListener on every host; 150 entries proposed; a second
   replica added and started in join mode so it catches up by snapshot.
   - (a) the leader records `OnSnapshotSendStarted` then `OnSnapshotSent`
     for shard 1 with the same Index, and no `OnSnapshotSendAborted`;
   - (b) the joiner records `OnSnapshotReceived` for shard 1 with From equal
     to the leader's replica ID and Index equal to the sent Index;
   - (c) the joiner's state machine restored from a snapshot
     (`Recoveries() > 0`) and holds the 150 entries.
   All waits poll against deadlines.
3. Per divergence from the docs: a failing test commit, then a fix commit
   in `pkg/internal/transport/quic.go` or `snapshot_recv.go`.
   Expected: the transport builds every transfer `SnapshotInfo` without
   `From`, so `OnSnapshotReceived` (and the send events) report From 0.
   The fix fills `From` from the chunk / header sender on every transfer
   event.

## Out of scope

- `OnSnapshotSendAborted` on a failed transfer (fault injection).
- Changes to helpers_test.go, wire or on-disk formats.
