# Plan: #922 CachedDiskStateMachine on a Host

Refs #744 (v1.0.0 bar test gap).

## Objective

`sm.NewCachedDiskStateMachine` is unit tested in pkg/sm/cached_test.go but has
never run on a Host. Prove, on a single-voter transportless Host with a real
WAL, that the documented contract (docs/multi-group-host/api.md
"CachedDiskStateMachine", docs/state-machines/api.md "Write-through cache")
holds end to end: reads are served from the cache, a stale or declined value is
never served, and values survive a shard restart.

## Slices

1. `docs: plan for #922` - this file.
2. `test:` pkg/host_cached_disk_sm_test.go, with a test-local file-backed
   key-value DiskStateMachine (put, delete, put-if-absent; state and
   lastApplied persisted to the Open dir) wrapped in the cache, an
   `ExtractKV` for every command and an `EntryApplied` that reports a
   declined put-if-absent. Assertions:
   - (a) after a put, SyncRead and StaleRead return the value, and a repeated
     read raises `CacheStats` hits;
   - (b) an overwrite and a delete are visible to the next SyncRead;
   - (c) a put-if-absent the inner machine declines leaves the first value
     served (SyncRead and StaleRead);
   - (d) mutating a returned value does not change the next read;
   - (e) after StopShard and StartShard every key reads back its last value
     (deleted key absent, declined key at its first value).
3. Per divergence from the docs: a failing `test:` commit, then a `fix:`
   commit in pkg/sm/cached.go, or a doc correction in
   docs/multi-group-host/api.md where the code is right.

## Out of scope

- Snapshot transfer, RecoverFromSnapshot and multi-replica clusters.
- LRU eviction policy (unit tested in pkg/sm).
- Any wire or on-disk format change.
