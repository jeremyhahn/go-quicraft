# #955: Host-level CRL revocation test

Refs #744 (v1.0.0 bar test gap).

## Objective

`config.RevocationConfig` documents that the transport rejects a revoked peer
certificate at handshake time, re-reads CRL files on each `CheckInterval` tick
when their content changes, and calls `OnCertRevoked` with the serial as a
lowercase hex string. Only the transport package tests this; at the Host level
only the field copy is tested. This row proves the documented behaviour
through three real Hosts.

## Slices

1. `docs: plan for #955` (this file).
2. `test:` pkg/host_crl_revocation_test.go, package quicraft. The test builds
   its own CA, three leaf certificates and PEM CRLs (crypto/x509
   CreateRevocationList); test/testpki is not edited. Three Hosts with mTLS
   and the same RevocationConfig (Mode crl, short CheckInterval, one CRL file
   in t.TempDir, an OnCertRevoked recorder) run a three-replica shard:
   - (a) with the CRL listing Host three's certificate, Hosts one and two
     elect a leader and commit proposals, replica three applies none of them,
     and OnCertRevoked on Host one or two reports Host three's serial in
     lowercase hex;
   - (b) after the CRL file is rewritten with an empty CRL, replica three
     catches up to every committed entry;
   - (c) OnCertRevoked never reports the serial of Host one or two.
   All waits are bounded condition polls; helpers take context.Context first.
3. Per divergence from the docs: a failing `test:` commit, then a `fix:`
   commit in pkg/host.go (or a doc correction in pkg/config/transportconfig.go
   where the code is right). A bug outside pkg/host.go is reported, not fixed.

## Out of scope

- OCSP modes, soft-fail behaviour, CA rollover (covered in the transport
  package).
- Any edit to test/testpki or to the transport package.
- Wire or on-disk format changes.
