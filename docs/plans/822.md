# #822: RequestCompaction after a snapshot trims the log and a restart recovers

Objective: prove, on an in-process single-replica shard over the disk LogDB,
that a snapshot followed by `RequestCompaction` trims the log and that a
Host reopened on the same directories recovers the same state machine.

Slice 1 (this PR), `pkg/log_compaction_recovery_test.go`:
- shard with a small `CompactionOverhead` and a hashing KV state machine;
- propose 200 entries, `SyncRequestSnapshot`, `RequestCompaction`;
- `LogRange` first index is above 1 and at most the snapshot index;
- `QueryRaftLog` below the first index fails with `logdb.ErrCompacted`;
- propose a few entries past the snapshot so the restart replays a tail;
- close, reopen on the same WAL and NodeHost dirs, restart the shard and
  assert `StateMachineHash` equals the value read before the close.

A bug found here gets a failing test commit, then the fix in `pkg/host.go`.

Out of scope: multi-replica compaction, on-disk state machines, any
wire or on-disk format change.
