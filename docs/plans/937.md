# Plan: #937 — a disk state machine's Sync runs before each snapshot capture on a Host

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/state-machines/user.md says a disk state machine's `Sync()` is called
before every snapshot capture. The adapter (pkg/internal/rsm/adapter.go,
`onDiskSMWrapper.saveSnapshotGated`) calls `Sync`, then `PrepareSnapshot`
(the capture), then `SaveSnapshot`; that order is tested only at the adapter
level. This row checks it end to end through `Host.SyncRequestSnapshot`,
including the error path.

## Slices

1. This plan.
2. pkg/host_ondisk_sync_snapshot_test.go: a test disk state machine that
   records `Update`, `Sync`, `PrepareSnapshot` and `SaveSnapshot` calls in
   order and can be told to fail `Sync`. Tests (all named `OnDiskSyncSnapshot`):
   - (a) after proposals, `SyncRequestSnapshot` returns an index; the record
     shows `Sync` after the last `Update` at or below that index and before
     `PrepareSnapshot`/`SaveSnapshot`;
   - (b) a second snapshot after more proposals has its own `Sync` before
     its capture;
   - (c) with `Sync` failing, `SyncRequestSnapshot` errors wrapping the SM's
     error, no capture is recorded, the previous snapshot index is still the
     latest, and the shard still accepts proposals and reads;
   - (d) once `Sync` succeeds again, the next snapshot succeeds.
3. Per divergence from the docs: a failing `test:` commit, then a `fix:`
   commit in adapter.go or host.go (or a doc fix in user.md where the code
   is right).

## Out of scope

Other state-machine tiers, snapshot streaming, and any wire or on-disk
format change.
