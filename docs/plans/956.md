# Plan for #956: batch config defaults and SubmitNoCopy errors

Tracked under #744 (v1.0.0 bar test gap).

## Objective

`pkg/batch/aggregator.go` documents `DefaultConfig` as the production defaults,
`WithConfig` as replacing zero-valued fields with defaults, and `SubmitNoCopy`
as returning the same errors as `Submit`. No test pins those three claims. Add
`pkg/batch/config_nocopy_errors_test.go` that does.

## Slices

1. Test commit, `pkg/batch/config_nocopy_errors_test.go`:
   - `TestDefaultConfig_HoldsDocumentedDefaults`: every field equals its
     `Default*` constant.
   - `TestWithConfig_ZeroFieldsKeepDefaults`: an all-zero `Config` leaves the
     aggregator's config equal to `DefaultConfig()` and its queue capacity at
     `DefaultQueueSize`; a `Config` with exactly one field set changes only
     that field.
   - `TestSubmitNoCopy_ClosedError`: after `Close`, `SubmitNoCopy` and `Submit`
     return an error matching `ErrClosed` and `*ClosedError`.
   - `TestSubmitNoCopy_QueueFullError`: `QueueSize` 1, `MaxBatchSize` 1 and a
     blocked proposer; once the queue holds one proposal both calls return
     `*QueueFullError`.
   - `TestSubmitNoCopy_ContextErrors`: a cancelled context yields an error
     matching `context.Canceled`, an expired deadline `context.DeadlineExceeded`,
     for both calls.
   - `TestSubmitNoCopy_FlushErrorWrapsProposerError`: a failing proposer yields
     a `*FlushError` that matches the proposer's error with `errors.Is`, for
     both calls.
2. Per divergence from the docs: a failing test commit, then a fix commit in
   `pkg/batch/aggregator.go` (or a doc-comment correction there when the code
   is right).

Waits are channels and bounded condition polls, never a bare sleep.

## Out of scope

- Any change to batching behaviour or the wire format.
- Tests of `Submit`'s copy semantics (already covered in regression_test.go).
