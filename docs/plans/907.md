# Plan: #907, dragonboat Sync*WithIdentity add calls

Refs #744 (v1.0.0 bar test gap).

## Objective

contrib/dragonboat/README.md says the compatibility NodeHost's
`SyncRequestAddReplicaWithIdentity`, `SyncRequestAddNonVotingWithIdentity`
and `SyncRequestAddWitnessWithIdentity` add a member bound to a peer identity,
refuse an address that fails `IsValidAddress` with `ErrInvalidAddress`, and
translate host errors so that they still match the quicraft error through
`errors.Is`. No test calls any of the three. This row adds one.

## Slices

1. This plan.
2. contrib/dragonboat/nodehost_identity_add_test.go, single-voter shards
   (newTestNodeHost, startTestShard). A witness votes, so adding one to a
   single-voter shard whose other replicas are not running loses quorum, as
   adding a voter does: each of those adds is the last on its shard, and its
   result is read from the replica's local membership (`ShardMembership`),
   because a linearizable read has no quorum to answer it. Order:
   - each of the three calls with an invalid address returns
     `ErrInvalidAddress` and leaves the membership unchanged;
   - non-voting replica 2 with an identity: listed in `NonVotings`, and its
     identity in the quicraft host's `Identities`;
   - replica 4 reusing replica 2's identity fails with an error matching
     `quicraft.ErrDuplicateMemberIdentity`;
   - witness replica 3, on a second shard: listed in `Witnesses`, identity
     present;
   - voter replica 5 last on the first shard: listed in `Nodes`, identity
     present.
3. Per divergence from the README: a failing test commit, then a fix commit
   in contrib/dragonboat/nodehost.go or errors.go (or a README correction
   when the code is right).

## Out of scope

The async `Request*WithIdentity` calls, the transport-backed identity check,
and any wire or on-disk format change.
