# Plan for #982: dragonboat snapshot and compaction events on a real NodeHost

Tracked under #744 (v1.0.0 bar test gap).

## Objective

Check on a running dragonboat NodeHost that a SystemEventListener receives
the snapshot and compaction events `raftio.ConvertEventListeners` converts
and `pkg/host.go` delivers, which `events_test.go` leaves as no-ops.

## Slices

1. `contrib/dragonboat/test/integration/events_snapshot_test.go`
   (`TestIntegration_DB_SnapshotEvents_*`), with a recording listener:
   - (a) after writes and `SyncRequestSnapshot` with an overridden
     compaction overhead, `SnapshotCreated` fires with shard, replica and a
     non-zero index, and `LogCompacted` for the same shard after it.
   - (b) `LogDBCompacted` fires for that compaction, after `LogCompacted`,
     with the same index.
   - (c) on a three-node shard that snapshots and compacts, a fourth
     replica added later is sent the snapshot and its host fires
     `SnapshotRecovered` with that shard and an index at or above the
     snapshot's.
   - (d) a listener that panics in `SnapshotCreated`, `LogCompacted` and
     `LogDBCompacted` does not stop the shard: a later snapshot and later
     writes still succeed.
2. Per divergence from the docs: a failing test commit, then a fix commit
   in contrib/dragonboat/raftio/events.go or pkg/host.go.

## Out of scope

- Any change to a wire or on-disk format version.
- The send-side snapshot events and connection events.
