# Plan: #939 RegisterSession with a chosen client ID (Refs #744)

## Objective

Close the v1.0.0 bar test gap on caller-chosen client IDs.
docs/client-sessions/user.md ("Choose the client ID yourself", "Size the
limits") promises that `RegisterSession` refuses a client ID the shard holds
with a `*SessionError`, that entries left from an earlier session under the
same ID are answered as expired and never applied a second time, and that
`MaxTotalSessions` bounds the session table. None of this is tested through a
Host; `MaxTotalSessions` is tested only at the policy and protocol level.

## Slices, in order

1. This plan.
2. `pkg/host_register_session_test.go`, one Host on the in-memory LogDB with a
   counting state machine, test names under `RegisterSessionClientID`:
   - (a) registering client ID X twice: the second returns a `*SessionError`
     (`errors.As`), and the first session still proposes;
   - (b) after `CloseSession` on X, registering X again succeeds, and an entry
     built from the earlier session with its old series ID is answered as
     expired and not applied a second time;
   - (c) with `MaxTotalSessions` N, N registrations succeed, the next returns a
     `*SessionError`, and after one `CloseSession` it succeeds;
   - (d) every proposal on an open session is applied exactly once throughout.
3. Per divergence from the docs: a failing test commit, then a fix commit in
   pkg/host.go; a doc wrong where the code is right is corrected in
   docs/client-sessions/user.md instead.

## Out of scope

- Per-owner caps (covered by host_session_owner_test.go).
- On-disk state machines (sessions are refused there).
- Any wire or on-disk format change.
