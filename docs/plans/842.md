# Plan for #842: per-owner session cap through the public Host API

## Objective

docs/client-sessions/api.md and docs/client-sessions/architecture.md say
`Host.NewSessionWithOwner` fails with a `*SessionError` wrapping
`ErrInvalidOperation` once an owner holds `MaxSessionsPerOwner` sessions,
other owners are unaffected, owner 0 is never counted or capped,
`RegisterSession` of a `NewSessionWithOwner` session is held to the same cap,
and `CloseSession` frees the owner's slot. Until now the cap was tested only
inside pkg/internal/session; no test drove it through `Host`.

## Slices

1. This plan.
2. pkg/host_session_owner_test.go, `TestHostSessionOwnerCap`: a
   single-replica Host with `MaxSessionsPerOwner = 2`:
   - two `NewSessionWithOwner(ctx, 1, A)` succeed with `OwnerID() == A`;
   - the third fails, `errors.As(*SessionError)` and
     `errors.Is(ErrInvalidOperation)`;
   - owner B registers;
   - three owner-0 sessions register (`NewSession` and
     `NewSessionWithOwner(..., 0)`);
   - `RegisterSession(NewSessionWithOwner(1, id, A))` is refused the same way;
   - after `CloseSession` of one A session completes, a new A
     `NewSessionWithOwner` and an A `RegisterSession` each succeed in turn.
3. Per divergence from the docs: a failing test commit, then a fix commit in
   pkg/host.go (or a doc fix in docs/client-sessions/api.md when the code is
   right).

## Out of scope

- The cap's internal accounting (covered by
  pkg/internal/session/owner_cap_test.go).
- Multi-replica and restart/snapshot replay of the owner table.
- Any wire or on-disk format change.
