# Plan: #968 observability guide examples

Refs #744 (v1.0.0 bar test gap).

## Objective

The metrics and logging setups in docs/observability/user.md (lines 20-91)
run as checked Go examples, so a drift between the guide and the code fails
`go test`.

## Slices

1. This plan.
2. pkg/example_metrics_test.go (package quicraft_test), each example with an
   `// Output:` block:
   - `ExampleNewPrometheusMetricsCollector`: the collector goes through
     `WithMetrics` to a Host with a running shard; its `Registry` is served
     with `promhttp` on an `httptest.Server`; the scrape contains
     `quicraft_metrics_per_shard_enabled 0` and a `quicraft_raft_` series.
   - `ExampleNewPrometheusMetricsCollectorWithConfig`: `PerShardMetrics: true`
     reports `quicraft_metrics_per_shard_enabled 1`.
   - `ExampleNewSampledMetricsCollector`: a 1-in-100 sampled wrapper goes
     through `WithMetrics`; a proposal commits.
   - `ExampleNoOpMetricsCollector`: a type embedding `NoOpMetricsCollector`
     overrides `RegisterShard` and sees shard 1 registered.
   - `ExampleWithLogger`: `config.NewLogger` in JSON mode goes through
     `WithLogger`; the shard starts.
   Helpers take `context.Context` first and reuse `exampleHostConfig` and
   `waitReadReady` from pkg/example_host_test.go.
   The guide points each matching block at its example.
3. Per divergence: a failing test commit, then a fix commit in
   pkg/metrics_prometheus.go or pkg/metrics.go; a doc wrong where the code
   is right is corrected in the guide.

## Out of scope
