# #773: config.Config Validate names every rejected field

Objective: one table test proves `(*Config).Validate` and
`(*Config).ValidateElectionTimeout` reject every out-of-range field with
the documented error type, and that the error text names the field.

Slices, in order:

1. `pkg/config/config_validate_table_test.go` (new): each row starts from
   `validConfig()` and changes one field. Reject rows cover every branch of
   validateIdentity, validateTiming, validateSizeLimits, validateSessions,
   validateCompression, validateLeaseRead and validateDataDir, asserting
   `*ValidationError` (Field equal to the name) or the typed error from
   `errors.go` via `errors.As`, and the name in `Error()`. Accept rows pin
   each boundary value (MaxInt32 ticks, protocol size maxima, expiry 100,
   drift min/max, the largest ElectionRTT that does not overflow).
2. A bug found: a failing test commit, then the fix in config.go/errors.go.

Out of scope: new validation rules for fields Validate does not check
today, other packages, wire or on-disk formats.
