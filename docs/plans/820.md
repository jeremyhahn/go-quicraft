# #820: a witness keeps quorum without applying entries; the witness limit holds

Objective: prove end to end, on real in-process hosts over QUIC, that a witness
replica counts toward quorum, never applies user entries to a state machine,
and that the replicated witness policy refuses a witness add that breaks it.

Slice (one test, `pkg/witness_replica_test.go`):
1. Three hosts (testpki leaves); replicas 1 and 2 bootstrap a full shard.
2. Host 3 joins as a witness (`IsWitness`); the leader adds it with
   `SyncRequestAddWitnessWithIdentity` (a transport host refuses an add
   without an identity, so the plain `SyncRequestAddWitness` cannot be used).
3. Propose entries; stop the leading full replica; proposals still commit
   on the surviving full replica with the witness's vote and acks.
4. The witness's state machine applied no user entry; the full one did.
5. Add witnesses until an add fails; the error is `ErrTooManyWitnesses` or
   `ErrBreaksFullReplicaMajority` (errors.Is).

A witness bug found: failing test commit first, then the fix in pkg/host.go.
Out of scope: policy changes, observers, wire or on-disk formats.
