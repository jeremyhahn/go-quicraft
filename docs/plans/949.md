# Plan: #949 snapshot reader and hash tests

Objective: pin the documented behaviour of `DecompressingSnapshotReader`
(pkg/internal/engine/snapshot_pool.go) and `HashSnapshotReader`
(pkg/internal/engine/snapshot_integrity.go), neither of which a test in
pkg/internal/engine calls directly. v1.0.0 bar test gap, tracked under #744.

## Slices

1. This plan.
2. pkg/internal/engine/snapshot_reader_test.go (package engine):
   - `TestDecompressingSnapshotReaderRoundTrip`: for `NoCompression` and
     `Snappy`, an empty payload, a small one and one larger than a snappy
     block (64 KiB) written through the matching writer
     (`snappy.NewBufferedWriter` for Snappy) read back unchanged.
   - `TestDecompressingSnapshotReaderNoCompressionReturnsSameReader`.
   - `TestDecompressingSnapshotReaderUnknownType`: out-of-range values give a
     nil reader and `errors.Is(err, ErrUnsupportedSnapshotCompression)`.
   - `TestDecompressingSnapshotReaderSnappyRejectsRawBytes`: non-snappy
     bytes fail with an error and never yield the raw bytes.
   - `TestHashSnapshotReaderMatchesFileHash`: xxhash64 and exact length,
     equal to the file form (`hashSnapshotData`; the brief's
     "HashSnapshotFile") over a file holding the same bytes.
   - `TestHashSnapshotReaderReadFailure`: a reader failing part way returns
     (0, 0, the error).
3. Per divergence from the docs: a failing test commit, then a fix commit in
   snapshot_pool.go or snapshot_integrity.go (or a doc fix where the code is
   right).

## Out of scope

Recovery/receive/import call sites, the snappy or xxhash libraries
themselves, and any wire or on-disk format change.
