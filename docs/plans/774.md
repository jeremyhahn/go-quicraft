# Plan for #774: HostConfig and TransportConfig Validate reject every out-of-range field

Objective: a table test proving `(*HostConfig).Validate` and `(*TransportConfig).Validate`
reject every out-of-range field with a typed error from `pkg/config/errors.go` whose
text names the field.

Slices, in order:

1. `pkg/config/hostconfig_validate_table_test.go` (new):
   - a base HostConfig: zero value plus the required fields (WALDir, NodeHostDir,
     RaftAddress, ListenAddress, DeploymentID, MTLSConfig), then `SetDefaults`;
     asserts `Validate` passes on it;
   - one row per rejection branch of HostConfig.Validate (including LogConfig and
     KeyRotationInterval) and of TransportConfig.Validate (limits, receive budget,
     mTLS, revocation), each changing one field; asserts `errors.As` to the named
     type and that `err.Error()` names the field;
   - a valid row for the KeyRotationInterval-without-MaxRetainedEpochs warning path.
2. A branch that accepts an invalid value gets a failing test commit, then the fix.

Out of scope: other Validate methods (ShardConfig and the like), wire or on-disk
formats, behaviour changes beyond a found bug.
