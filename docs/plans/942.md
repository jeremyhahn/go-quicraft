# Plan for #942: LeaderHandler lifecycle on a real Host

## Objective

`pkg/leaderexec.go` documents that `RegisterLeaderHandler` may be called
before `StartShard`, that the registration outlives `StopShard`, that a
second call replaces the handler, and that after `UnregisterLeaderHandler`
a request already executing finishes while later ones get
`ErrLeaderHandlerNotRegistered`. The existing tests drive a synthetic
cluster; none checks these promises on a real Host. This row adds that
test.

## Slices

1. `docs/plans/942.md` (this plan).
2. `pkg/host_leader_handler_lifecycle_test.go`: a single-replica Host from
   `newTestHost` and `testShardConfig`, where `ExecuteOnLeader` runs in
   process. Subtests of `TestHost_LeaderHandlerLifecycle`:
   - (a) a handler registered before `StartShard` answers once the shard
     leads, and its reply is returned unchanged;
   - (b) after `StopShard` and `StartShard` the same handler answers
     without registering again;
   - (c) after a second `RegisterLeaderHandler` only the new handler runs;
   - (d) a handler blocked on a channel: `UnregisterLeaderHandler` during
     the request lets it return its reply once released; the next call
     gets `ErrLeaderHandlerNotRegistered`;
   - (e) a handler registered for another shard ID is never called.
3. Per divergence from the docs: a failing test commit, then a fix commit
   in `pkg/leaderexec.go` (or a doc correction where the code is right).

## Out of scope

- Multi-replica forwarding (covered by `pkg/leaderexec_test.go`).
- Any wire or on-disk format change.
