# Plan for #944: async membership calls complete with the effect of the sync form

Tracked under #744 (v1.0.0 bar test gap).

## Objective

`Host.RequestAddNode`, `RequestAddObserver`, `RequestAddWitness` and
`RequestRemoveNode` return a `*RequestState`. Tests cover their pre-flight
errors and one observer add, but none checks that each async form completes
through its `RequestState` with the same membership effect as its `Sync` form.

## Slices

1. `docs/plans/944.md` (this file).
2. `pkg/host_async_membership_test.go`, on transportless Hosts from
   `newTestHost` and `testShardConfig`, one fresh single-voter shard per
   subtest (a voting add raises the quorum, so a shard is not reused after
   one):
   - (a) `RequestAddObserver` returns a `*RequestState` whose `Result`
     completes without error; the membership then lists the replica as an
     observer and `ConfigChangeID` has advanced.
   - (b) `RequestRemoveNode` of that observer with the new `ConfigChangeID`
     completes; the replica is in no membership set and is listed in
     `Removed`.
   - (c) `RequestAddWitness` and `RequestAddNode` each complete and list the
     replica as a witness or a voter.
   - (d) each async form called with a `configChangeIndex` older than the
     current one returns `*StaleConfigChangeError` at once with a nil
     `*RequestState`, and the membership is unchanged.
   - (e) each completed `RequestState` releases (a later `Result` returns
     `ErrReleased`), and the membership role sets match those the `Sync`
     form produces on a twin shard.
3. Per divergence from the docs: a failing `test:` commit, then a `fix:`
   commit in `pkg/host.go` (or a doc correction in
   `docs/membership-changes/user.md` where the code is right).

The membership is read with `ShardMembership` polled until the change is
applied locally: after a voting add the single-voter shard has lost its
quorum, so the linearizable `SyncGetShardMembership` cannot complete.

## Out of scope

- The `...WithIdentity` variants and hosts with a transport.
- Joining the added replica (no second host is started).
- Any wire or on-disk format change.
