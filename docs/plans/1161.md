# #1161: code-review workflow template v5.10.11 → v5.11.3

`.github/workflows/code-review.yml` is the handbook's
`software/templates/github-actions/code-review.yml` (handbook main `dc8643d`,
after `93c1eae2`), with this repository's CUSTOMIZE values spliced back in by
marker. Line 1 reads `# code-review-template: v5.11.3`.

## Diff against the template outside the CUSTOMIZE blocks

Empty. The copy is byte-identical to the template (`cmp` reports no
difference), because this repository's values at the template's CUSTOMIZE
points are the template's defaults:

| CUSTOMIZE point | This repository (base `64ee78e9`) | Template v5.11.3 |
|---|---|---|
| `COORDINATOR_TURNS` (workflow env) | `3` | `3` |
| opencode job `runs-on` | `qwen` | `qwen` |
| `NO_REVIEW_PATHS` (gate job env, new in v5.11.0) | not present | template default (ruling 589 list) |
| `vars.OLLAMA_URL` | repository variable, not in the file | same |

## What the copy drops: the repo-local ruling-443 skip guard

The v5.10.11 copy carried two `# CUSTOMIZE (per repository …)` …
`# End of CUSTOMIZE.` blocks (`PROTECTED`, `CI_FILE`, `GATE_JOB`). They were not
template blocks: they are the head of the `GUARD_PY` heredoc in the repo-local
"Owner ruling 443" scope step (#720, #721: a workflow-only PR gets no review
when InfoSec's guard Y-1 to Y-8, Y-10 passes), once in the codex job and once in
the opencode job, plus the `steps.scope.outputs.skip != 'true'` conditions that
step added to later steps. The handbook template has never carried that step.

Template v5.11.0/v5.11.1 (ruling 589) replace it: the required
`Code Review (codex)` check is a `gate` job that passes on a Codex approval of
the head or on a change wholly inside `NO_REVIEW_PATHS` (`docs/`, `*.md`,
`.github/`, `.gitea/`, `changelog.d/`). A workflow-only PR therefore still
needs no review, but the InfoSec Y-checks on such a PR (protected workflow
stems, the CI gate's `needs` list) no longer run. Keeping the two blocks would
mean keeping the whole ruling-443 step, and the diff against the template would
not be empty, so this copy follows the template.

The splice script asserts the mismatch before it writes: the template has 0
marker blocks, the repository 2, and each of the repository's blocks is the
head of a `GUARD_PY` heredoc inside the ruling-443 step, which the template
does not contain. Each single-line CUSTOMIZE point occurs once in each file
(`NO_REVIEW_PATHS` occurs only in the template).
