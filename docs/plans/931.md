# #931: NodeHost.GetShardInfo matches the Host for every state machine kind

Refs #744 (v1.0.0 bar test gap).

## Objective

contrib/dragonboat/README.md documents that `NodeHost.GetShardInfo` returns
the shard's `ShardInfo`, and false when the shard is not loaded here. The
existing tests check only ShardID, ReplicaID and a non-nil Nodes. This row
pins the remaining fields against the Host's own `ShardInfo` and
`GetLeaderID`, for each of the three state machine kinds.

## Slices

1. Plan (this file).
2. `contrib/dragonboat/nodehost_shard_info_test.go`:
   - (a) for a regular, a concurrent and an on-disk state machine, after a
     leader is elected, `GetShardInfo` returns found=true; LeaderID, Term,
     IsLeader, IsObserver and IsWitness equal `nh.host.ShardInfo` and
     `GetLeaderID`; StateMachineType is 1, 2 and 3 respectively;
   - (b) on the idle shard Pending is false and PendingProposals is 0;
   - (c) after `StopShard` GetShardInfo returns found=false and a nil error;
     for a shard never started it returns found=false and a nil error.
3. Per divergence from the docs: a failing test commit, then a fix commit in
   contrib/dragonboat/nodehost.go (or a README.md correction when the doc is
   the wrong side).

## Out of scope

- Multi-replica shards, observers and witnesses (role flags are checked only
  against the Host, on a single-voter shard).
- Any change to the Host's `ShardInfo` or wire/on-disk formats.
