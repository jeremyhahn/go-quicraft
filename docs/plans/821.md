# #821: HealthCheck reports every shard state a caller can put a shard in

Objective: pin `Host.HealthCheck` (`pkg/host.go`) for each state a caller can
drive a shard or host into, against the documented `HealthStatus` and
`ShardInfo` values (`pkg/info.go`).

Slice 1: `pkg/host_healthcheck_states_test.go`, a table test on an in-process
Host covering a shard started and led, paused, resumed and stopped, the host
draining and closed. Each row asserts `Status`, `ShardCount`, the shard's
`Shards` entry (`Health`, `Paused`, `IsLeader`, `LeaderID`) and the documented
JSON field names of `HealthStatus` and `ShardInfo`.

A wrong status found gets a failing test commit, then the fix in `pkg/host.go`
or `pkg/info.go`. Found: a paused replica kept its frozen pre-pause leader
claim (IsLeader, LeaderID self, Health healthy); `buildShardInfo` now reports
no leader while paused.

Out of scope: sealed barrier and disk-full rows (covered by `TestHealthCheck_*`
in `pkg/host_test.go`), multi-host shards, wire formats.
