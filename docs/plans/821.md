# #821: HealthCheck reports every shard state a caller can put a shard in

Objective: pin `Host.HealthCheck` (`pkg/host.go`) for each state a caller can
drive a shard or host into, against the documented `HealthStatus` and
`ShardInfo` values (`pkg/info.go`).

Slice 1 (this lane): `pkg/host_healthcheck_states_test.go`, a table test on an
in-process Host (memory LogDB, no transport) covering a shard started and led,
paused (`PauseShard`), resumed (`ResumeShard`), stopped (`StopShard`), the host
draining (`Drain`) and the host closed. Each row asserts `Status`,
`ShardCount`, and the shard's `Shards` entry (`Health`, `Paused`, `IsLeader`,
`LeaderID`), and that the result marshals to JSON with the documented field
names (`status`, `barrier_sealed`, `disk_ok`, `shard_count`, `shards`,
`diagnostics_dropped`, and per shard `shard_id`, `health`, `paused`, ...).

A wrong status found on the way gets a failing test commit, then the fix in
`pkg/host.go` or `pkg/info.go`.

Out of scope: sealed barrier and disk-full rows (already covered by
`TestHealthCheck_*` in `pkg/host_test.go`), multi-host shards, wire formats.
