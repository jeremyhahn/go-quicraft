# #814: proposals past the in-memory log limit return ErrSystemBusy and recover

Objective: prove on an in-process shard that a proposal past the per-shard
`MaxInMemLogSize` or the host-wide `MaxTotalInMemLogSize` is refused with an
error matching `ErrBusy` (and `ErrSystemBusy` for the global limit), that no
call blocks past its context deadline, and that once the log drains proposals
succeed again and every acknowledged proposal is applied.

Slices:
1. `pkg/proposal_busy_limit_test.go`: a state machine whose Update blocks on a
   channel; `TestBusyLimit_PerShard` and `TestBusyLimit_Global` propose until a
   call fails, assert the error, unblock, assert recovery and applied set.
2. Only if a limit is not enforced: a failing test commit, then the fix in
   `pkg/host.go` or `pkg/internal/engine`.

Out of scope: multi-node feedback (RateLimit messages), wire or on-disk
format changes, other backpressure paths (queue full, ReadIndex).

## Review fix

`TestBusyLimit_PerShard` stayed refused at 16380/16384 under load: a defect.
`inMemory.appliedLogTo` runs only from `Peer.Commit` with the `LastApplied`
an update carried; `Peer.HasUpdate` ignores `lastApplied`, so once the last
batch applies with nothing else pending, no update truncates it and the
per-shard limiter (releases below 70%) stays tripped. Test commit: one
proposal larger than the limit, applied, must leave the in-memory size at 0.
Fix: `HasUpdate` reports pending truncation; `GetUpdate` truncates itself
when the update is ReadOnly (never committed). Limit check unchanged.

## Scope amendment

The fix lives in `pkg/internal/raft/peer.go`, outside the original map
(`pkg/host.go`, `pkg/internal/engine`): only the Raft peer knows its in-memory
log still holds applied entries. `HasUpdate` reports them through
`appliedReleasePending`; `GetUpdate` releases them on a ReadOnly update. The
change runs for every shard, limited or not, so `peer_test.go` pins it: the
pending release is reported once, a ReadOnly update releases it, an idle shard
without `MaxInMemLogSize` quiesces, and an update with entries to save
releases nothing above lastApplied.
