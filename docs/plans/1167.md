# Plan: #1167 refuse NoSyncWAL outside test binaries

## Objective

`HostConfig.Validate` only logged a warning for `NoSyncWAL`, so a test or
benchmark config copied into production silently dropped the
fsync-before-ack guarantee. Validate now refuses `NoSyncWAL=true` with the
typed `ErrNoSyncWALOutsideTest` unless the process is a test binary.

The gate is `testing.Testing()` rather than a build-tag file pair: every
caller that sets `NoSyncWAL` is a `_test.go` file, `go test` (including
`-bench`) builds a test binary, and pkg/seal/kdf.go and
pkg/crypto/shamir already gate test-only paths this way.

## Slices

1. Test commit: `pkg/config/nosyncwal_test.go`
   - test binary (default seam): `NoSyncWAL=true` validates and warns;
   - non-test binary (seam `isTestBinary` returns false): `NoSyncWAL=true`
     returns an error matching `errors.Is(err, ErrNoSyncWALOutsideTest)`
     whose message names `NoSyncWAL`; `NoSyncWAL=false` validates.
   Fails on base: the seam and the error do not exist.
2. Fix commit:
   - `pkg/config/errors.go`: `ErrNoSyncWALOutsideTest` /
     `NoSyncWALOutsideTestError` (sentinel + `Is`).
   - `pkg/config/hostconfig.go`: `var isTestBinary = testing.Testing`;
     Validate refuses before `warnDisabledSafetyFlags`; field and helper
     comments state the rule.
   - `pkg/config/hostconfig_test.go`: stale "not rejected" comment.
   - docs/multi-group-host/api.md and engineering.md state the rule.

## Out of scope

- Other safety flags (config.go `warnDisabledSafetyFlags` on `Config`).
- Changing any caller: all are `_test.go` files and keep working.
