# #967: shards on overlapping replica sets stay independent

Objective: prove that two shards whose replica sets overlap but differ are
independent. Every existing integration test places each shard on every host
(`startShard` in `test/integration/host/helpers_test.go`), so nothing checks
that a host failure touches only the shards it hosts, or that a host which
does not host a shard refuses it.

Slice 1 (this lane), `test/integration/host/partial_placement_test.go`
(build tag `integration`, package `host_test`):
- a local helper that starts a shard on a chosen subset of a four-host
  cluster (members, `MemberIdentities` and trackers for that subset only);
- (a) shard A on hosts 1-3, shard B on hosts 2-4: each elects a leader and
  commits a write;
- (b) stop host 1: shard B's leader and term are unchanged and B keeps
  committing; shard A elects a leader among hosts 2-3 and keeps committing;
- (c) on host 4, `SyncRead` and `SyncPropose` for shard A fail with
  `ErrShardNotFound`, `ShardInfo(A)` fails the same way, and
  `NodeHostInfo` lists B but not A.

Every new helper takes `context.Context` first, before `*testing.T`.

Out of scope: membership changes moving a shard between hosts, and restarting
host 1. A divergence from the docs gets a failing test commit, then a fix
commit in the host package file the failing path names.
