# Plan for #933: dragonboat async membership calls

Refs #744 (v1.0.0 bar test gap).

## Objective

contrib/dragonboat/README.md says `RequestAddReplica`, `RequestAddWitness` and
`RequestDeleteReplica` fail at once, with a nil `RequestState`, for a change
invalid against the current membership. The existing async success tests only
read a result and never check the membership. Prove that the async calls
complete and change `GetShardMembership`, and that an invalid change fails at
once with a nil `RequestState`.

## Slices

1. Test, `contrib/dragonboat/nodehost_async_membership_test.go`, on a
   single-replica shard of `newTestNodeHost` (no transport):
   - (a) `RequestAddNonVoting` of replicas 2 and 3 with the current
     `ConfigChangeID` completes within 5 s; `GetShardMembership` lists both in
     `NonVotings` and `ConfigChangeID` grows.
   - (b) `RequestDeleteReplica` of 3 completes; 3 is in `Removed` and not in
     `NonVotings`.
   - (c) `RequestDeleteReplica` of 3 again and `RequestAddNonVoting` of the
     removed 3 each return an error and a nil `RequestState`.
   - (d) on a shard with `OrderedConfigChange` true, `RequestAddNonVoting`
     with a stale `ConfigChangeID` errors at once or yields `Rejected()`,
     never `Completed()`.
2. Per divergence from the docs: a failing test commit, then a fix commit in
   `contrib/dragonboat/nodehost.go` (or a README correction where the doc is
   wrong and the code right).

## Out of scope

- Adding voting replicas or witnesses (would cost the single-replica shard
  its quorum).
- Hosts with a transport and the `WithIdentity` variants.
- Any wire or on-disk format change.
