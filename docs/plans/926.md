# Plan: #926 leader self-removal hands over without losing acknowledged writes

Tracked under #744 (v1.0.0 bar test gap).

## Objective

docs/membership-changes/engineering.md ("Leader self-removal") and
docs/membership-changes/api.md (Errors) say a remove of the leader's own
replica commits like any other, after which the leader steps down and the
remaining voters elect a new one. The existing remove test
(pkg/membership_remove_readd_test.go) removes only a follower. This row adds
an end-to-end test over three QUIC hosts running the in-memory kv state
machine that removes the leader itself.

## Slices

1. `docs: plan for #926` - this file.
2. `test:` pkg/membership_remove_leader_test.go,
   `TestRemoveLeader_HandsOverAndLosesNoAcknowledgedWrite`:
   - (a) 30 acknowledged puts; `SyncRequestRemoveNode` of the leader's own
     replica ID, sent to the leader, returns nil or an error for which
     `MaybeApplied` is true; the membership read from a survivor lists that
     replica in `Removed` and not in `Nodes`.
   - (b) the two survivors elect a new leader within an election-timeout
     bound, and every acknowledged put reads back through `SyncRead` on it.
   - (c) further puts through the new leader succeed and read back.
   - (d) the removed host never again reports itself leader of the shard,
     and a proposal on it fails with a documented error.
3. Per divergence from the docs: a failing `test:` commit, then a `fix:`
   commit in pkg/host.go or pkg/internal/raft/raft.go; a doc that is wrong
   where the code is right is corrected in
   docs/membership-changes/engineering.md instead.

## Out of scope

- Leader transfer before removal (covered by leader_transfer_test.go).
- Re-adding the removed replica (covered by membership_remove_readd_test.go).
- Wire or on-disk format changes.
