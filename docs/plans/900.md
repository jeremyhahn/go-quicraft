# Plan: #900 — the WithIdentity add calls commit the identity and refuse a duplicate or removed one

Refs #744 (v1.0.0 bar test gap).

## Objective

docs/membership-changes/api.md says the `WithIdentity` add calls commit the
new replica's identity in `Membership.Identities`, refuse an identity an
active member holds (`ErrDuplicateMemberIdentity`), refuse an identity the
shard removed under any replica ID (`ErrRemovedMemberIdentity`, listed in
`Membership.RemovedIdentities`), and refuse to promote a witness through
`AddNode` (`ErrNodeAlreadyExists`). No test calls
`SyncRequestAddNodeWithIdentity` or `RequestAddWitnessWithIdentity`.

## Slices

1. This plan.
2. pkg/host_identity_add_test.go, `TestHostIdentityAdd*`, on single-voter
   transportless Hosts (one Host per subtest):
   - (a) `SyncRequestAddWitnessWithIdentity` commits replica 2 in
     `Witnesses` with `Identities[2] == testIdentity(2)`;
   - (b) `RequestAddWitnessWithIdentity` for replica 3 with `testIdentity(2)`
     completes with `ErrDuplicateMemberIdentity`;
   - (c) after removing witness 2, an add of replica 4 with `testIdentity(2)`
     fails with `ErrRemovedMemberIdentity` and `RemovedIdentities` holds it;
   - (d) `SyncRequestAddNodeWithIdentity` for the witness ID fails with
     `ErrNodeAlreadyExists`;
   - (e) `SyncRequestAddNodeWithIdentity` commits replica 5 as a voter with
     `Identities[5] == testIdentity(5)` (last change on its Host).
3. Per divergence from the docs: a failing test commit, then a fix commit in
   pkg/host.go (or a doc correction in docs/membership-changes/api.md where
   the code is right).

## Out of scope

Observer identity adds (covered elsewhere), transport-backed identity
enforcement, any wire or on-disk format change.
