# Plan for #964: wire-protocol reference examples compile and check output

Tracked under #744 (v1.0.0 bar test gap).

## Objective

`docs/wire-protocol/api.md` shows the Entry codec (`Size`, `MarshalTo`,
`UnmarshalFrom`), the entry-slice pool (`GetEntrySlice`, `PutEntrySlice`) and
the message-type helpers (`MessageTypeName`, `IsFreeOrderMessage`) in snippets
no build checks. Make each a compiled Go example with an `// Output:` block in
`pkg/proto/example_test.go` and point the guide blocks at them.

## Slices, in order

1. This plan.
2. Test commit: `pkg/proto/example_test.go` (package `proto_test`):
   - `ExampleEntry_MarshalTo`: an Entry with term, index, type and command
     marshals into a buffer of exactly `Size()` bytes; `MarshalTo` returns
     that length; `UnmarshalFrom` consumes the same length and restores equal
     fields; a buffer one byte shorter than `Size()` returns
     `ErrBufferTooSmall`.
   - `ExampleGetEntrySlice`: a pooled slice starts empty, takes appends, and
     `PutEntrySlice` resets it to length zero.
   - `ExampleMessageTypeName`: `Replicate` prints its name, 9999 prints
     `Unknown(9999)`; `IsFreeOrderMessage` prints true for `Replicate` and
     false for `ReplicateResp`.
   The guide's code blocks in `docs/wire-protocol/api.md` name the example
   that compiles them.
3. Per divergence between code and docs: a failing test commit, then a fix
   commit in `pkg/proto/` (or a doc correction when the code is right).

## Out of scope

Other codec types (`Message`, `MessageBatch`, `Snapshot`, ...),
`ConfigChangeTypeName`, `StateMachineTypeName`, and any wire or on-disk format
change.
