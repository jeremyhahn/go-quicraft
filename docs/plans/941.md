# Plan: #941 live-shard diagnostics

Refs #744 (v1.0.0 bar test gap).

## Objective

`Host.DiagShardGates`, `Host.DiagPipelineState` and `Host.DiagRemotes` are
documented in `pkg/info.go` (`ShardGatesDiag`, `PipelineDiag`, `RemotesDiag`)
and in `docs/raft-consensus/user.md` ("Diagnose a stuck shard"), but are
tested only for `ErrClosed`. Prove on a live single-replica shard that each
reports what its doc says.

## Slice (one test file: `pkg/host_diag_live_test.go`)

A state machine whose `Update` and `SaveSnapshot` can each be held on a
channel. Tests, all named `TestDiagLive_*`:

1. Idle shard: `DiagShardGates` reports `Saving` false, `Recovering` false,
   `ApplyInFlight` 0; `DiagPipelineState.PendingProposals` is 0.
2. `SaveSnapshot` held during `RequestSnapshot`: `Saving` turns true within a
   bounded wait, and false after release.
3. `Update` held with k proposals outstanding: `PendingProposals` reaches k,
   and returns to 0 once they apply.
4. Single-replica leader: `DiagRemotes.Text` is the documented text (or the
   warming-up text before the first publication), never an error.
5. A shard ID that is not started: each method returns `ErrShardNotReady`.

Per divergence from the docs: a failing test commit, then a fix commit in
`pkg/host.go`, or a doc correction in `pkg/info.go` or
`docs/raft-consensus/user.md` where the code is right.

## Out of scope

`Recovering` true (needs a snapshot install from a peer), multi-replica
remotes text, `DiagRaftState`, wire or on-disk formats.
