# #837: witness policy update — replication, restart, refusal

## Objective

Prove at the Host level what docs/membership-changes/user.md (Change the
witness policy) and docs/membership-changes/engineering.md promise for
`Host.SyncRequestUpdateWitnessPolicy`: the policy is replicated state that
every replica adopts and reports through `ShardMembership`, survives a
restart, refuses a policy the current membership already violates, and
honours the `configChangeIndex` staleness guard.

## Harness

`newExecCluster` (pkg/leaderexec_test.go) never starts its engines, so no
config change can commit through it. The test file carries its own local
helper instead, built the way `newFailoverCluster` builds its cluster: three
real Hosts over mTLS running one shard, plus spare Host identities for the
witness replicas (a witness is admitted by membership only; it never needs to
run while three full replicas hold the quorum). A replica restarts by closing
its Host and opening a new one on the same directories, certificate and
address.

## Slice (one test commit)

pkg/host_witness_policy_test.go:

- (a) update the policy (MaxWitnesses=1) and see it in `ShardMembership` on
  every replica;
- (b) with one witness admitted, a second witness add returns
  `ErrTooManyWitnesses`;
- (c) with two witnesses admitted under MaxWitnesses=2, tightening to
  MaxWitnesses=1 returns `ErrTooManyWitnesses` and leaves the policy as it was;
- (d) an update carrying a stale `configChangeIndex` is refused;
- (e) a restarted replica reports the updated policy.

Per divergence from the docs: a failing `test:` commit, then a `fix:` commit
in pkg/host.go or pkg/internal/raft/membership.go (or a doc correction when
the doc is wrong).

## Out of scope

- `ErrBreaksFullReplicaMajority` on a policy update: it needs at least as many
  witnesses as full replicas, so the quorum needs a running witness; the
  validator is covered by the raft package unit tests.
- Any change to wire or on-disk formats.
