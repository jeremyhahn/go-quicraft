# Plan: #902 — ReadIndex refused by the shard (Refs #744)

## Objective

Cover the documented `OnReadIndexDropped` contract (docs/multi-group-host/api.md,
Raft events table): when `Host.ReadIndex` cannot hand the read to the shard's
ReadIndex queue it returns `ErrSystemBusy`, fires `OnReadIndexDropped` with the
shard's `EventShardInfo`, and rolls back the pending read and pending-op count.

## Slices

1. `docs: plan for #902` — this file.
2. `test: a ReadIndex the shard cannot take returns ErrSystemBusy, fires
   OnReadIndexDropped and leaves nothing pending` — new
   pkg/host_readindex_dropped_test.go, `TestReadIndexDropped_*`:
   - single-replica transportless Host, listener records OnReadIndexDropped;
   - after the leader is elected, fill the engine node's ReadIndex queue with
     `DeliverReadIndex` until it refuses, then call `h.ReadIndex`, retrying
     until it fails or 5 s pass;
   - asserts: `errors.Is(err, ErrSystemBusy)`; nil RequestState; event fired
     with ShardID 1, ReplicaID 1; `pendingReads` holds no entry beyond those
     present before the call; `Drain` returns promptly (no leaked pending op).
3. Per divergence from the docs: a failing `test:` commit, then a `fix:`
   commit in pkg/host.go (or a doc correction if the code is right).

## Out of scope

- Any change to the ReadIndex batching, queue sizes or other events.
- Wire or on-disk formats.
