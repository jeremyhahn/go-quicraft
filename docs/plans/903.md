# Plan: #903 NodeHost.ReloadMutualTLS test gap

Refs #744 (v1.0.0 bar test gap).

## Objective

contrib/dragonboat/README.md (ReloadMutualTLS row), the
`NodeHost.ReloadMutualTLS` doc comment and docs/multi-group-host/api.md
(ReloadMTLS) say the call re-reads `CAFile`, `CertFile` and `KeyFile`, uses
them for new handshakes, refuses a changed node identity
(`ErrNodeIdentityChanged` inside a `*MTLSReloadError`, `ErrMTLSReload`),
changes nothing on a failed check, and returns `ErrClosed` on a closed host.
No test calls `ReloadMutualTLS`. This row adds one.

## Slices

1. `contrib/dragonboat/nodehost_reload_mtls_test.go`: a NodeHost built as
   TestExampleConfig_NewNodeHost (testpki CA, LeafFiles in a temp dir,
   MutualTLS, kernel-assigned address), with subtests:
   - (a) CertFile rewritten with `ca.Reissue` of the same key: nil error,
     NodeIdentity unchanged;
   - (b) CertFile and KeyFile rewritten with a fresh `ca.Leaf`: error matches
     `quicraft.ErrNodeIdentityChanged` and `quicraft.ErrMTLSReload`,
     NodeIdentity unchanged; after restoring the original files a reload
     succeeds;
   - (c) CertFile not PEM: error, NodeIdentity unchanged, host still
     serving (a reload after restoring the file succeeds);
   - (d) after Close: error matches `dragonboat.ErrClosed`
     (= `quicraft.ErrClosed`).
2. Per divergence from the docs: a failing test commit, then a fix commit in
   contrib/dragonboat/nodehost.go (or README.md when the doc is wrong).

## Out of scope

- Handshake-level checks that new connections use the reloaded material
  (covered by the transport and pkg ReloadMTLS tests).
- CA rollover, peer-certificate exclusivity, WithoutTransport.
