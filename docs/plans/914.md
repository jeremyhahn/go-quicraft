# Plan for #914: NotifyCommit and CommittedC

Tracked under #744 (v1.0.0 bar test gap).

## Objective

docs/multi-group-host/api.md and pkg/config/hostconfig.go say that with
`HostConfig.NotifyCommit` on, `RequestState.CommittedC()` receives one early
result once the entry is durable in the local WAL, with Value 0 and nil Data,
before the state machine applies it; that `ApplyResultC()` is the same
channel as `ResultC()`; that with NotifyCommit off CommittedC never receives
a value; and that both channels are nil after `Release`. No test sets
NotifyCommit. This row adds one.

## Slices

1. `pkg/host_notify_commit_test.go` on a single-voter transportless Host with
   a real WAL:
   - (a) 50 `Propose` calls: CommittedC delivers exactly one result, Value 0,
     nil Data, nil Err;
   - (b) once ApplyResultC has delivered, the committed result is already
     there (checked without blocking after the apply result);
   - (c) `ApplyResultC()` and `ResultC()` are the same channel;
   - (d) after `Release`, CommittedC and ApplyResultC are nil;
   - (e) NotifyCommit off: 20 proposals apply while CommittedC stays empty;
   - (f) a proposal refused on a paused shard (`ErrShardPaused`) delivers
     nothing on CommittedC.
2. Per divergence from the docs: a failing test commit, then a fix commit in
   pkg/host.go or pkg/requeststate.go (or a doc fix in api.md where the code
   is right).

## Out of scope

Multi-voter commit notification, transport paths, and any change to the
NotifyCommit API or wire/on-disk formats.
