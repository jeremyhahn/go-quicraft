# Plan: #916 entry compression end to end on a Host

## Objective

docs/multi-group-host/engineering.md ("Compression") and
docs/raft-consensus/engineering.md say that with
`Config.EntryCompressionType = config.Snappy` the leader compresses
`EntryNormal` payloads at proposal time, ORs `proto.EntryCompressFlag` into the
entry type, leaves incompressible data as is, stores entries compressed in the
WAL and decompresses `Entry.Cmd` before the state machine. Only
pkg/internal/raft tests this today; no Host test sets EntryCompressionType.
This row adds that Host-level test.

## Slices

1. `pkg/host_entry_compression_test.go`: a single-voter transportless Host on
   a real WAL (`NewHost(cfg, WithoutTransport(), WithoutEncryption())`), shard
   config with `EntryCompressionType = config.Snappy`, a state machine that
   records each applied Cmd by index and implements `sm.Hasher`.
   - (a) a 64 KiB run of one byte, a 4 KiB crypto/rand payload and a 1-byte
     payload, each via SyncPropose, reach the state machine byte for byte;
   - (b) `QueryRaftLog` over those indexes: the compressible entry carries
     `EntryCompressFlag` with a Cmd shorter than 64 KiB; the random and
     1-byte entries carry no flag and their Cmd unchanged;
   - (c) a session proposal (`NewSession`, then `SyncProposeWithSession`)
     under compression applies once and returns its result;
   - (d) Close and restart on the same directories with the same config: the
     state machine replays the same Cmds at the same indexes and
     `StateMachineHash` equals the value before the restart;
   - (e) a restart with `NoCompression` still applies the compressed entries
     already in the log unchanged.
2. Per divergence from the docs: a failing `test:` commit, then a `fix:`
   commit in pkg/internal/engine/apply.go or pkg/internal/raft/compress.go
   (or a doc correction where the code is right).

## Out of scope

Transport `MessageBatch` compression, decompression-bomb limits (tested in
pkg/internal/engine), multi-replica replication of compressed entries, and
any wire or on-disk format change.
