# Plan: #921 batch Aggregator on a real Host

Refs #744 (v1.0.0 bar test gap).

## Objective

`docs/write-batching/user.md` says an `Aggregator` built with
`batch.NewAggregator(batch.HostProposer{Host: h})` packs concurrent `Submit`
calls for one shard into one proposal that the state machine unpacks with
`batch.DecodeBatch`, that each `Submit` returns only after its batch is
applied, and that `Submit` after `Close` fails. `pkg/batch` is tested only
with a fake proposer. Prove the documented behaviour on a real Host.

## Slices

1. `pkg/host_batch_aggregator_test.go` (new): a single-voter transportless
   Host with a real WAL and a test-local state machine that decodes every
   entry with `DecodeBatch` and counts entries and commands.
   - (a) 64 goroutines each Submit 50 distinct commands: every Submit
     returns nil, each of the 3200 commands is applied exactly once, and
     fewer than 3200 entries were applied.
   - (b) `SubmitNoCopy` of a buffer the caller never touches again is
     applied unchanged.
   - (c) a Submit under an already-cancelled context returns an error
     matching `context.Canceled`, and its command is never applied.
   - (d) after `Close`, `BatchLen` is 0, Submit fails with `ErrClosed`, and
     a second `Close` returns nil.
   - (e) a Submit to a shard not on the Host returns an error matching
     `ErrShardNotFound`.
2. Per divergence from the docs: a failing test commit, then a fix commit in
   `pkg/batch/aggregator.go` or `pkg/batch/hostproposer.go`, or a doc fix in
   `docs/write-batching/user.md` where the code is right.

## Out of scope

- Multi-replica batching, transports, sessions, and metrics assertions.
- Any wire or on-disk format change.
