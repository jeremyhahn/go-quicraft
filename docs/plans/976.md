# Plan: #976 Peer.RejoinAfterPause test gap

Refs #744 (v1.0.0 bar test gap).

## Objective

`Peer.RejoinAfterPause` (pkg/internal/raft/peer.go) has no direct test. Its
documentation promises: the replica rejoins as a follower at its current term;
the vote cast in the term is kept; a follower keeps the leader it knew; a
leader or candidate rejoins with no leader; nothing is persisted (term and vote
unchanged); a fresh election timeout is armed. Pin each promise with a test.

## Slices

1. `docs: plan for #976` - this file.
2. `test: Peer.RejoinAfterPause ...` - new
   pkg/internal/raft/rejoin_after_pause_test.go, one table over the roles
   follower-with-leader, leader, candidate and pre-candidate:
   - (a) follower: term, vote and leader unchanged; still a follower;
   - (b) leader: follower in the same term, no leader, vote unchanged;
   - (c) candidate / pre-candidate: as (b), and a RequestVote from another
     replica in that term is refused (vote already cast);
   - (d) every case: the next GetUpdate carries the same HardState as the
     update before the rejoin, so the rejoin persists nothing;
   - (e) every case: ticking past the election timeout starts a campaign
     (RequestPreVote or RequestVote is sent).
3. Per divergence from the documentation: a failing `test:` commit, then a
   `fix:` commit in peer.go or raft.go (or a doc fix where the code is right).
