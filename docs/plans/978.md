# #978: install verdict registry tests

Refs #744 (v1.0.0 bar test gap).

## Objective

Cover the engine node's install verdict registry
(`AwaitInstallVerdict`, `CancelInstallVerdict`, `signalInstallVerdict`,
`abandonInstallVerdicts` in pkg/internal/engine/node.go) directly, including
the stop (`Stop`) and fail (`markFailed`) paths that today are reached only
indirectly.

## Slices

1. `docs: plan for #978` (this file).
2. `test:` pkg/internal/engine/install_verdict_test.go (package engine):
   - (a) `AwaitInstallVerdict` on a stopped node and on a failed node returns
     a channel already holding `InstallAbandoned`.
   - (b) a second `AwaitInstallVerdict` at the same index answers the first
     channel `InstallSuperseded`; the second channel gets the later verdict.
   - (c) after `CancelInstallVerdict` a signal for that index delivers
     nothing; cancelling an index never registered is harmless.
   - (d) with several indexes registered, `Stop` answers each channel
     `InstallAbandoned` exactly once; `markFailed` does the same.
   - (e) under `-race`, concurrent registers, cancels and a stop: every
     channel is answered at most once, and every channel not cancelled is
     answered after the stop.
3. Per divergence between code and docs: a failing `test:` commit, then a
   `fix:` commit in node.go (or a doc-comment correction where the code is
   right).

## Out of scope

- The step worker's verdict production (covered by incarnation_fence_test.go).
- Any wire or on-disk format change.
