# Plan for #946: AwaitRestart and the contained-diagnostics worker

Refs #744 (v1.0.0 bar test gap).

## Objective

Pin the documented behaviour of `AwaitRestart` and of the contained-diagnostics
worker (`newDiagnosticWorker`, `submit`, `drain`, `runContained`) in
pkg/internal/supervise with direct tests. Until now only `LogContained` and
`Supervise` drive them.

## Slices

1. This plan.
2. pkg/internal/supervise/await_worker_test.go (package supervise):
   - `TestAwaitRestart_ClosedStopReturnsFalseAtOnce`: closed stopC returns
     false well under `RestartDelay`.
   - `TestAwaitRestart_OpenStopWaitsRestartDelay`: open stopC returns true,
     not before `RestartDelay` has elapsed.
   - `TestAwaitRestart_StopDuringWaitReturnsFalse`: stopC closed during the
     wait returns false before `RestartDelay` has elapsed.
   - `TestDiagnosticWorker_DropsPastCapacityAndRunsInOrder`: worker of
     capacity 4 with a blocking first record drops exactly the records
     submitted past capacity (dropped counter), then runs the kept records in
     submission order once released.
   - `TestDiagnosticWorker_SurvivesPanickingRecord`: a panicking record does
     not stop the next; the worker goes idle (running false) afterwards.
   - `TestDiagnosticWorker_ConcurrentSubmitRunsEachOnce`: many goroutines
     submit into a worker large enough for all; each record runs once.
   Channels and bounded waits on conditions only; a fresh worker per case.
3. Per divergence between code and doc: a failing test commit, then a fix
   commit in supervise.go (or a doc-comment fix where the code is right).

## Out of scope

Changes to `Supervise`, `RunResilient`, `RunEach`, `LogContained`; the
package-level `contained` worker; any other package.
