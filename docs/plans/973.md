# Plan: #973 — the quic-transport guide's config rules as checked examples

Refs #744 (v1.0.0 bar test gap).

## Objective

`docs/quic-transport/user.md` shows Go blocks that no example compiles or
runs. Turn the guide's configuration rules into `Example` functions with
`// Output:` blocks so `go test` checks them, and point each guide block at
its example.

## Slices, in order

1. This plan.
2. Test commit:
   - `pkg/config/example_transport_test.go` (package `config_test`):
     - `ExampleTransportConfig_SetDefaults`: a zero `TransportConfig` gets
       `UDPRecvBufSize` and `UDPSendBufSize` of 7 MB each; a value set before
       the call is kept.
     - `ExampleTransportConfig_Validate_revocation`: a revocation config in
       mode `"crl"` with a CRL path validates; mode `"ocsp"` with no
       `OCSPResponderURL` is refused with a `*config.ValidationError` naming
       `TransportConfig.RevocationConfig.OCSPResponderURL`.
   - `pkg/example_transport_test.go` (package `quicraft_test`):
     - `ExampleHost_NodeIdentity`: a Host built with `WithoutTransport`
       reports an empty `NodeIdentity`. Reuses `startExampleShard`.
   - `docs/quic-transport/user.md`: the revocation, limits and
     no-transport blocks name their example.
3. Per divergence between code and guide: a failing test commit, then a fix
   commit in `pkg/config/transportconfig.go` or `pkg/host.go` (or a doc fix
   where the code is right).

## Out of scope

- Blocks that need certificate material or a multi-node cluster
  (`MTLSConfig`, `ReloadMTLS`, `SyncRequestAddNodeWithIdentity`).
- The FIPS build recipe (shell, not Go).
- Any change to wire or on-disk formats.
