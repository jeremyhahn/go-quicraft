# Plan: #960 full-cluster cold restart (Refs #744)

## Objective

No integration test stops every host of a shard at once and reopens them all
from disk. `rolling_restart_test.go` always keeps a quorum up, so it never
proves that the persisted log, hard state and snapshots alone are enough to
bring a shard back. This row adds that test.

## Slices

1. `docs: plan for #960` — this file.
2. `test:` — `test/integration/host/full_cluster_restart_test.go`
   (build tag `integration`, package `host_test`),
   `TestHostAPI_FullClusterRestart_KeepsAcknowledgedWrites`:
   - (a) start a shard on three hosts (`newTestClusterWithRestart`,
     snapshot-enabled config), write a known set of entries with
     `proposeNEntries` and record each acknowledged one;
   - (b) close all three hosts;
   - (c) reopen all three on the same directories (`restartNode`) and wait
     until exactly one host reports itself leader and every host names
     that same replica as leader;
   - (d) every acknowledged entry is on every host (`verifyAllData`), no
     host holds a key that was never written, every state machine has
     applied at least up to the pre-close applied index, and no entry is
     applied twice (`assertApplyOrder`: an applied index that does not
     advance is a duplicate or replayed apply);
   - (e) a new write after the restart commits and is visible on all three.
3. Per divergence between code and docs: a failing `test:` commit, then a
   `fix:` commit in the host package file the failing path names (or a
   docs/ correction where the code is right).

New helpers take `context.Context` first, before `*testing.T`.

## Out of scope

- Restart with changed membership, identities or addresses.
- On-disk state machines; crash (kill -9) rather than orderly Close.
- Any wire or on-disk format change.
