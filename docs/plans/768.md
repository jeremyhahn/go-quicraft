# #768: fuzz targets for the snapshot transfer header and chunk decoders

Objective: fuzz the two decoders a peer drives on the snapshot path,
`SnapshotHeader.UnmarshalFrom` (snapshot_header.go) and the chunk framing loop
`snapshotReceiver.receiveChunks` (frame header, `SnapshotChunk.UnmarshalFromWindow`,
`validateChunk`), in a new `pkg/internal/transport/fuzz_snapshot_test.go`.

Slices, in order:
1. `FuzzSnapshotHeaderUnmarshalCrash`: arbitrary bytes never panic; short input is
   `ErrBufferTooSmall`; a full header re-encodes to the first 56 input bytes.
2. `FuzzSnapshotHeaderRoundTrip`: seven fields encode then decode to the input.
3. `FuzzSnapshotChunkStreamCrash`: arbitrary bytes into `receiveChunks` never panic,
   every reserved byte of the memory budget is returned, and a delivered snapshot
   holds exactly the declared chunk count with data within `maxSnapshotChunkDataLen`.
4. `FuzzSnapshotChunkRoundTrip`: a chunk built from fuzzed fields, framed by the
   encoder, is delivered by `receiveChunks` equal to the input.
Seeds are valid headers and chunk frames built by the encoders.
A found bug gets a seed under testdata/fuzz and a test commit before its fix.

Out of scope: wire or on-disk format changes, the QUIC stream setup, the sender.

## Review fix

`FuzzSnapshotChunkStreamCrash` checked only the budget counters, so an allocation made
before the budget check, or an oversized one followed by a decode error, passed. It now
measures `runtime.MemStats.TotalAlloc` around `receiveChunks` (run on the fuzz goroutine)
and fails past `allocBound = 2*fuzzSnapshotMemory + 2*len(data) + 1<<20`: the frame buffer
is allocated only after `reserveChunkMemory` admits it (at most `fuzzSnapshotMemory/2` per
peer), each decoded chunk copies at most its frame, and 1 MiB covers logging and timers.
New seeds: a frame past `MaxFrameSize`, a frame within it but past the per-peer budget, and
a valid frame followed by a truncated one. Proven by moving the allocation above the check.

## Review fix 2

The round 1 bound (at least 3 MiB) let a 512 KiB + 1 frame buffer allocated before
`reserveChunkMemory` pass. `FuzzSnapshotChunkStreamCrash` now walks a copy of the stream
with the receiver's own functions (`readFrameHeaderWindow`, the budget arithmetic,
`UnmarshalFromWindow`, `validateChunk`) to compute `admitted`, the frame bytes the receiver
reserves, and fails past `allocBound = k*admitted + allocSlack` (k = 1: the decoder aliases
Data into the frame buffer; `allocSlack` = 64 KiB). `FuzzSnapshotHeaderUnmarshalCrash`
requires `UnmarshalFrom` to allocate nothing. Proven by moving the frame allocation above
the budget check and seeing the line-192 seed fail.
