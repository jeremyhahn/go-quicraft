# Plan for #979: dragonboat NodeHost ExportPath and shard-settings refusals

Refs #744 (v1.0.0 bar test gap).

## Objective

Cover the two refusals in `contrib/dragonboat` that no test reaches:

- `checkExportPath` (nodehost.go), called by `SyncRequestSnapshot` and
  `RequestSnapshot`, returns `ErrDirNotExist` when `SnapshotOption.ExportPath`
  is missing or is not a directory.
- `validateStartReplica` (nodehost.go), called by `StartReplica`, wraps a
  `dbConfig.Config.Validate` failure in `*ShardSettingsError`.

## Slices

1. `docs: plan for #979` (this file).
2. `test:` contrib/dragonboat/nodehost_refusal_test.go, on `newTestNodeHost`:
   - `TestExportPath_SyncRequestSnapshot_Refused`: ExportPath a missing
     directory and a regular file: `errors.Is(err, ErrDirNotExist)`; the
     missing path is still absent and the file is unchanged.
   - `TestExportPath_RequestSnapshot_Refused`: the same two paths through the
     async `RequestSnapshot`: same error, no RequestState, nothing exported.
   - `TestExportPath_ExistingDir_Exports`: an existing empty directory:
     both calls succeed and the directory then holds snapshot files.
   - `TestShardSettings_InvalidConfig_Refused`: zero ReplicaID, and
     ElectionRTT not above HeartbeatRTT: `errors.As` finds
     `*ShardSettingsError`, its `Err` is the `Validate` error, `errors.Is`
     matches `ErrInvalidShardSettings`, and the shard is not started.
3. Per bug found: a failing `test:` commit, then a `fix:` commit in
   nodehost.go or errors.go.

## Deviation from the brief

`ExportSnapshot(ctx, shardID, io.Writer)` takes a writer, not a path, and
does not call `checkExportPath`; the path-based caller besides
`SyncRequestSnapshot` is `RequestSnapshot`, so (b) is tested there.

## Out of scope

`ExportSnapshot` writer failures, `ImportSnapshot`, other Start*Replica
variants, and any change to wire or on-disk formats.
