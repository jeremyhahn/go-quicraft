# Plan for #930: remove-then-compact on a dragonboat NodeHost

Refs #744 (v1.0.0 bar test gap).

## Objective

Pin the documented behaviour of the StopShard, RemoveData and
RequestCompaction sequence on the dragonboat-compatible `NodeHost`
(contrib/dragonboat): the sequence succeeds on a shard that is no longer
loaded, the removed replica cannot restart (also after the NodeHost is
reopened on the same directories), and a replica ID that does not match
the loaded replica returns `ErrShardNotFound`.

## Slices

1. Test: contrib/dragonboat/nodehost_remove_compact_test.go,
   `TestNodeHost_RemoveCompact_Sequence`:
   - (a) after 20 `SyncPropose` calls and `SyncRequestSnapshot`,
     `RequestCompaction(shard, replica+1)` matches `ErrShardNotFound`;
   - (b) `StopShard`, `RemoveData(shard, replica)` returns nil, then
     `RequestCompaction(shard, replica)` returns a `SysOpState` whose
     `CompletedC` is already closed;
   - (c) `StartReplica` of the same shard and replica returns
     `ErrReplicaRemoved` and `HasNodeInfo` is false;
   - (d) a NodeHost reopened on the same directories still refuses the
     restart with `ErrReplicaRemoved`.
2. Per divergence from the docs: a failing test commit, then a fix commit
   in contrib/dragonboat/nodehost.go (or a README.md correction where the
   code is right and the doc is wrong).

## Out of scope

- Compaction semantics of the core quicraft host beyond the adapter.
- Any wire or on-disk format change.
