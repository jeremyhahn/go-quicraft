# Row #1119: client-sessions

## Objective

Fold the row's open per-issue PRs into the single row branch
`row/1119-client-sessions`, ported onto current main, so they build and pass
together and land as one PR that closes #1119. Test files and guide text only;
no non-test code changes.

## Slices (in order, one commit each)

1. #1102 (issue #744): `pkg/config/sessions_per_owner_test.go`,
   `pkg/host_sessions_per_owner_unlimited_test.go`. An unset
   MaxSessionsPerOwner takes DefaultMaxSessionsPerOwner, and
   SessionsPerOwnerUnlimited lets one owner fill the shard up to
   MaxTotalSessions.
2. #986 (issue #947): `pkg/config/sessions_per_owner_test.go`, merged with the
   #1102 file of the same name. Config.SetDefaults gives an unset
   MaxSessionsPerOwner the default and keeps an explicit cap or
   SessionsPerOwnerUnlimited.
3. #917 (issue #972): `pkg/example_session_test.go`,
   `docs/client-sessions/user.md`. The guide's flows run as checked examples:
   ProposeWithSession with ProposalCompleted, a session with an owner, and a
   saved session.
4. #886 (issue #939): `pkg/host_register_session_test.go`,
   `docs/client-sessions/user.md`. RegisterSession refuses a client ID the
   shard holds, re-registers it after CloseSession without re-applying old
   entries, and MaxTotalSessions refusals.
5. Review P1 fix: `pkg/host_sessions_per_owner_unlimited_test.go` sets
   MaxTotalSessions to DefaultMaxSessionsPerOwner+2 and registers every slot
   for one nonzero owner, so a runtime that maps SessionsPerOwnerUnlimited to
   DefaultMaxSessionsPerOwner fails at registration #129; the shard-limit
   refusal and close/reopen checks stay.
