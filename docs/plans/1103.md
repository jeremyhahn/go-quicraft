# #1103 — one-replica leader steps down after adding a witness

## Symptom

`TestSyncRequestUpdateWitnessPolicy_EndToEnd` (pkg/host_test.go) failed on
main: the `SyncRequestAddWitness` that follows the witness-policy update
returned `not leader for shard 1, leader unknown (already submitted to raft;
it may still commit)`. It passed 200/200 locally; it fails only under CI load.

## Cause

Not the policy update. The witness add itself.

1. Once the AddWitness is applied, the leader's voting set is
   {replica 1, witness 10}, so quorum is 2.
2. `Peer.syncRaftRemotes` creates the witness's `remote` with `newRemote`,
   which starts **inactive**.
3. CheckQuorum (`tickLeader`) runs every `electionTimeout` ticks (10 ms at
   test settings) and `hasQuorumActive` counts only active remotes. If the
   boundary falls before the witness has had a chance to answer (it can be
   one tick after the change), the count is 1 of 2 and the leader steps down.
4. If the host has not yet completed the pending AddWitness when that
   happens, the request fails with ErrNotLeader (wrapped as MaybeApplied).

etcd/raft avoids this by creating new `Progress` with `RecentActive = true`,
which gives a new voter one CheckQuorum window to answer.

The test also has a second, correct, step-down. Its witness address
(127.0.0.1:6000) never runs, so one window later the leader really has lost
quorum. The test's last step (tightening the policy, expected to be rejected
with ErrBreaksFullReplicaMajority) could race that step-down too.

## Fix

- `raft.rebuildReplicaToBit` (called by `syncRaftRemotes` on a leader after a
  membership change) marks a voter that was not in the previous map as
  active. It gets one window of grace. The flag is cleared at the next
  boundary as usual, so a voter that never answers still costs the leader
  its leadership one window later.
- `becomeLeader` sets `replicaToBit = nil` before its rebuild. A new term
  grants no grace and earns every active flag afresh, which keeps
  `TestRaft_BecomeLeader_ClearsStaleRemoteActivity` valid.
- `TestSyncRequestUpdateWitnessPolicy_EndToEnd` turns CheckQuorum off. It
  tests the witness policy, and its witness never runs, so stepping down is
  correct and outside what the test asserts. The comment in the test says so.

## Tests

- `TestRaft_CheckQuorum_NewWitnessGetsOneWindowOfGrace`
  (pkg/internal/raft/raft_test.go) is deterministic. It applies the change one
  tick before the boundary and checks that the leader survives that
  boundary. It also checks that the leader steps down one full window later
  when the witness stays silent. The test fails before the fix.
