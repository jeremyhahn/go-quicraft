  Production-Readiness Review — go-quicraft (full codebase)

  Verification: every CRITICAL/HIGH below was confirmed by me directly in source unless marked otherwise.

  CRITICAL

  1. WAL drops session fields — at-most-once delivery breaks across crash recovery

  pkg/logdb/types.go:22, pkg/internal/engine/convert.go:25, pkg/logdb/reader.go:580
  logdb.Entry persists only Index/Term/Type/Cmd. proto.Entry's Key, ClientID, SeriesID, RespondedTo are dropped on write (the conversion comment even says so) and zeroed on replay. Since ClientID=0 means "not session-managed," every entry
  replayed from the WAL bypasses session dedup — a committed-but-unsnapshotted client request retried after restart applies twice, and session register/unregister sentinel entries are misrouted into the user SM. The documented
  exactly-once guarantee degrades to at-least-once exactly when it matters (crash recovery).
  Fix: add the four uint64s to logdb.Entry and the WAL entry record (header 44→76 bytes), carry through both conversions, bump the on-disk format version and gate old-format reads.

  2. Snapshot injection: membership check silently skipped for unloaded shards, sender identity forgeable

  pkg/messagehandler.go:202-216
  The snapshot sender check is if node != nil && !node.IsMember(from) — when GetNode(shardID) returns nil (shard not loaded locally), authorization is skipped and the snapshot is reassembled and persisted to LogDB, poisoning a later
  StartShard. Worse, the identity checked is the in-band chunk.From, which any mTLS-authenticated peer in the deployment can forge — the verified TLS identity is never bound to it. One compromised node can inject state into any shard on
  any node.
  Fix: fail closed (node == nil → reject + metric), and bind the snapshot stream's verified certificate identity (same mechanism as inboundAuthorizedForCached for SourceAddress) to the claimed From before any buffering or persistence.

  3. WAL recovery scans past zero-filled holes, resurrecting post-gap records

  pkg/logdb/waldb/segment.go:297-370
  The all-zero check breaks only the inner per-block loop; the outer loop keeps scanning subsequent blocks. A crash that loses block N while block N+1 reached the medium (fdatasync doesn't order inter-block writes) recovers records after
  the hole — a Raft log gap that violates Log Matching. The CRC-corruption path correctly stops (return records, nil at :334); the zero-hole path doesn't.
  Nuance from my verification: partial-block zero padding followed by data in the next block is the normal layout (padding is always < header size, mid-block), so the fix must distinguish: zeros starting at pos > 0 → padding, continue; a
  **wholly-zero block** is never legitimately written mid-stream → remember it, and if any later block is non-zero, stop recovery at the hole (and set stoppedAtCorruption).

  HIGH

  4. SaveState phase-2 fsync failure: no rollback, no poison (fsyncgate)

  pkg/logdb/waldb/db.go:1413-1416
  Write-phase failures roll back via discardDirtyShards; a sync-phase failure just returns the error, leaving written-but-unsynced bytes in segments. Post-fsync-failure, Linux may mark dirty pages clean — retry semantics are undefined,
  and ghost records can surface at recovery (chaining into #3's hole scenario). Every serious storage engine treats fsync failure as fatal.
  Fix: on syncDirtyShards failure, poison the DB (fail-stop: refuse further writes, force crash-recovery) rather than returning a retryable error. Rollback alone is insufficient because the truncation itself can't be proven durable after
  a failed fsync.

  5. CRL reload silently drops revocations on file-read failure

  pkg/internal/transport/revocation/checker.go:248-279
  A read failure logs and continues, then the partial newSet replaces the full revokedSet. A transiently unreadable CRL (deleted, perms, NFS blip) un-revokes every certificate in it. (Parse failures correctly abort and keep the old set;
  read failures don't.)
  Fix: on any per-file failure, keep the previous set and hashes, return an error; under EnforceRevocation surface staleness as handshake failure.

  6. CRL checking ignores EnforceRevocation — fail-open even in enforce mode

  checker.go:344-345, 377-382
  ModeCRL returns (checkCRL(serial), nil) — never an error. Empty/never-loaded CRL ⇒ everything passes, even with EnforceRevocation=true. The OCSP path honors enforcement; the CRL path doesn't.
  Fix: track last-successful-load; when enforcing and no fresh CRL is available, return an error from the CRL branches.

  7. AEAD invocation counter resets to zero on every restart — NIST 2^32 budget unenforced across process lifetimes

  pkg/seal/barrier.go:191-196, 361-508 (agent-verified)
  Random 96-bit nonces make the 2^32 invocation budget per DEK a hard safety bound, but the counter is in-memory only and Unseal never calls the existing Seed(). A frequently-restarted node can encrypt unbounded volumes under one epoch
  DEK with ShouldRotate never firing.
  Fix: persist per-epoch invocation counts (the WAL already tracks epochs per segment) and seed on Unseal; or refuse to unseal a non-empty WAL with an unseeded counter unless the embedder owns seeding (then document that contract loudly).

  8. Shamir primitive: unmaintained prime-field bignum dependency, not the GF(256) the docs claim

  pkg/crypto/shamir/shamir.go:23 → github.com/SSSaaS/sssa-golang (last commit 2017)
  The agent reported CRITICAL data-loss from trailing-zero truncation — my verification downgrades that: quicraft hex-encodes the secret first (shamir.go:44), so secret bytes are ASCII [0-9a-f], never 0x00, and the library's
  TrimRight(\x00) can only strip padding. Truncation is not reachable through this wrapper. What remains real: (a) CLAUDE.md/docs say "pure GF(256) primitive" — it's 256-bit prime-field math/big; (b) variable-time bignum arithmetic in a
  root-key custody path (timing side channel); (c) an unmaintained 2017 crypto dependency at the root of the trust stack.
  Fix: vendor a constant-time GF(256) implementation (HashiCorp Vault's shamir is the standard choice), keep the wrapper API, correct the docs.

  9. FIPS mode doesn't constrain the data-path cipher

  pkg/seal/fips.go:27, algorithm.go:190-195 (agent-verified, both agents independently)
  FIPS detection is "any non-empty GOFIPS140" and only switches the KDF (Argon2id→PBKDF2). SelectOptimalAlgorithm still returns ChaCha20-Poly1305 on non-AES-NI CPUs — a "FIPS" deployment silently encrypting everything with a non-approved
  cipher.
  Fix: under FIPS, force AES-GCM in SelectOptimalAlgorithm and reject ChaCha/XChaCha in BarrierConfig.validate(); consider keying detection off crypto/fips140 state rather than the raw env var.

  10. Snapshot save directory never fsynced

  pkg/internal/engine/snapshot_pool.go:393, 463, 954, 1341 (agent-verified)
  Files are fsynced; the directory (after MkdirAll, file create, and the encrypt-in-place os.Rename) is not. Crash ⇒ LogDB's durably-recorded snapshot points at a directory entry that may not exist. Multi-node clusters re-stream from the
  leader; a single-node deployment loses the snapshot and possibly the compacted entries it covered.
  Fix: reuse waldb's syncDirFS pattern after each snapshot file create/rename.

  11. RequestLeaderTransfer reports success for invalid targets

  pkg/host.go:3080-3124 (agent-verified with quoted raft-layer code)
  Raft validates the target (ErrNodeNotFound/ErrTransferTargetNotVoter/ErrTransferInProgress) but the error surfaces asynchronously in the step worker and is logged, never returned; the API returns nil unconditionally.
  Fix: pre-validate target against membership (non-zero, not self, voting member) at the Host layer; or route through a RequestState so the async error reaches the caller.

  MEDIUM

  12. ModeBoth revocation requires BOTH sources to confirm (checker.go:363) — a CRL-revoked cert with an OCSP "good" passes. It matches its doc, but it's the weakest composition and shouldn't exist as-is. Fix: revoked-by-either wins;
  treat "unknown" per EnforceRevocation.
  13. RevocationConfig.Mode unvalidated — any typo ("CRL", "strict") silently selects ModeAny. Fix: validate in TransportConfig.Validate().
  14. Seal()/Rotate() drop key enclaves without Clear() (barrier.go:525-529, 891) — DEK material lingers until GC finalizers. Fix: explicit Clear() on all live enclaves in seal().
  15. KDF accepts arbitrary caller params (kdf.go:110-130) — only salt length is validated; Time=1/Memory=1KiB/Iterations=1 silently produces a near-free wrapping key. Fix: enforce production floors, test-only escape hatch.
  16. No 0-RTT early-data gating on receive — no Used0RTT check anywhere (verified by grep); replayed early-data snapshot/message streams reach handlers. Default-off + Raft idempotency mitigate; snapshot path (esp. with #2) should reject
  streams on 0-RTT connections.
  17. GetNewSession/RegisterSession ignore ctx.Done() (host.go:2764, 2820) — cancelable-but-deadline-less contexts block indefinitely on quorum loss. Fix: select on rs.ResultC() vs ctx.Done() like SyncGetShardMembership.
  18. StartShard allowed while draining (host.go:1696) — wasted SM Open() + misleading lifecycle events during graceful shutdown. Fix: check h.draining.
  19. NoneStrategy decrypt of real-strategy ciphertext returns garbage silently (strategy_none.go:122) — no AEAD tag to fail on after a misconfigured restart. Fix: refuse non-zero epoch prefixes in None mode.
  20. RecordEpoch accepted by WAL validator but never written (record.go:139) — widens pre-CRC header matching; would abort recovery if ever decrypted. Fix: remove from valid set.
  21. Silent fallocate failure (segment.go:76-85) — Debug-level log defeats the ENOSPC-avoidance design. Fix: Warn + DiskMonitor.ForceCheck().

  24. Shamir Combine zero-digest skips integrity silently (shamir.go:140) — make skip explicit (option), not sentinel.
  25. Nonce tracker unbounded per epoch (aead_tracking.go:237) — bounded once #7 makes rotation real.
  26. Propose accepts empty cmd (host.go:2334) — burns a quorum round; dragonboat rejects.
  27. Config-change pre-registered address not rolled back on marshal/queue failure (host.go:4892).
  28. RateLimiter.Increase lacks the saturation its Decrease has (rate.go:50).
  29. Security drops (unauthorized message/snapshot) logged but not counted — add metrics so they're alertable.
  30. Empty PeerCertificates → accept in VerifyConnection (quic.go:81) — unreachable today, latent fail-open.
  31. 16MB frame allocation honored per stream × 65K stream worst case (authenticated peers only) — consider a tighter message-path cap.
  32. staticcheck nits: misleading break in select (snapshot_recv.go:236), unused applyRetries (node.go:203), SA4000 self-comparison in raft_test.go:757, two never-true error comparisons in tests.
